**Scope:** executability corrections after the main@348876c re-review (#308).
The M6R5 attestation *design* stands; this wave fixes the procedure order,

### Fixes delivered

| # | Finding | Resolution |
|---|---|---|
| 1 | Stale M6R3-era artifact set (tarball `347f11c2…`, 69-entry inventory w/o NOTICE, provenance `d2a07b2`, publish-first checklist, old-metric packet) still sat in the active `docs/releases/beta/` path | Quarantined to `docs/releases/history/m6r3/` as a frozen record (checksum set still verifies in place); active path now carries a DO-NOT-PUBLISH README and stays artifact-free until M6R6-ATT completes |
| 2 | Documented gate→rehearsal order deterministically failed (gate leaves untracked `release-evidence.json`; rehearsal refuses non-clean tree; gate hashed a tarball the rehearsal later rewrote) | Procedure reordered: benchmarks → rehearsal (clean tree) → `LUGAS_PERF_RELEASE=1 bun run verify` (release gate hashes the FINAL tarball, writes evidence) → builder last. Builder's own hints and header now state the required order |
| 3 | Checklist template `cd docs/releases/beta … cd ../..` left the owner in `docs/`, corrupting every later relative path (publish after tag push) | Template uses a subshell: `( cd docs/releases/beta && sha256sum --check SHA256SUMS )` |
| 4 | `attestationCommit` recorded but never verified; packet printed an unproven HEAD | Builder fails closed unless `evidence.attestationCommit` equals assembly HEAD (checked pre-verify and again on the evidence regenerated by the builder-executed verify) |
| 5 | Checklist pre-checked verify/typecheck/compat/clean-room PASS before `bun run verify` ran | Builder executes `LUGAS_PERF_RELEASE=1 bun run verify` itself during assembly and marks only what it proved (verify/typecheck/perf/rehearsal/clean-room/owner-decision files/tarball triple-hash); Compatibility-matrix and P0/P1-sweep are now explicit unchecked OWNER items |
| 6 | "0 open issues" while required attestation work remained | Standing blocker registered as #309 (M6R6-ATT) |

### Corrected attestation procedure (single checkout — `packageSourceCommit == attestationCommit`)

```bash
set -euo pipefail
unset LUGAS_BENCH_NO_ARCHIVE
PACKAGE_SOURCE_SHA="$(git rev-parse HEAD)"
export LUGAS_PACKAGE_SOURCE_SHA="$PACKAGE_SOURCE_SHA"
bun install --frozen-lockfile

# 1. Ignored benchmark archives — the tracked/untracked tree stays CLEAN.
bun run scripts/benchmark-plain.ts
bun run scripts/benchmark-validated.ts
bun run scripts/benchmark-client-types.ts

# 2. Rehearsal FIRST (refuses a dirty tree): writes the FINAL tarball,
#    provenance.json, inventory.json, sbom.json, package-rehearsal.json.
bun run release:package:rehearse

# 3. Release verification: verify.ts runs the perf gate in --release mode,
#    which hashes the FINAL rehearsal tarball and writes
#    docs/releases/beta/release-evidence.json (untracked is fine here).
LUGAS_PERF_RELEASE=1 bun run verify

# 4. Packet assembly LAST: re-executes verify itself, cross-validates
#    evidence ↔ rehearsal ↔ actual tarball, then writes packet/checklist/SHA256SUMS.
bun run scripts/release/build-beta-packet.ts --package-source-sha "$PACKAGE_SOURCE_SHA"

# 5. Commit the attested artifacts, then verify checksums from a CLEAN
#    checkout of that commit (subshell keeps cwd unchanged):
git add docs/releases/beta && git commit -m "release: M6R6-ATT attested beta artifacts"
git worktree add .worktrees/attest-check HEAD
( cd .worktrees/attest-check/docs/releases/beta && sha256sum --check SHA256SUMS )
git worktree remove .worktrees/attest-check
```

### Two-worktree variant (`packageSourceCommit` ≠ `attestationCommit`)

1. In the **package-source worktree** (HEAD = source commit): steps 1–2 above.
2. Copy into the **attestation worktree** (HEAD = attestation commit):
   `docs/releases/beta/{lugas-0.1.0-beta.1.tgz,provenance.json,inventory.json,sbom.json,package-rehearsal.json}`
   plus the benchmark archives `benchmarks/results/{m5-plain,m5-validated,m5-client-types}/`.
3. In the attestation worktree: `export LUGAS_PACKAGE_SOURCE_SHA=<source sha>`,
   then steps 3–5 above. The gate validates that the copied archives bind to
   the source commit; the builder validates `packageSourceCommit` against
   that SHA and `attestationCommit` against its own HEAD.

### Attestation status: ENVIRONMENT-LOCKED (unchanged in kind, corrected in method)

Run the M6R6 procedure on a quiet host (sustained load < 4); see #309 for
the acceptance list. Publication then follows the regenerated
`docs/releases/beta/CHECKLIST.md` (owner action, tag pinned to
`$PACKAGE_SOURCE_SHA`).

### Standing verdict (updated)

**GO for the source; publication HOLD until M6R6-ATT (#309) completes.**
The ledger now reflects this: #309 is the only open issue, and it closes
only when every acceptance box there is checked on a quiet-host run.
