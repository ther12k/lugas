## HTTP vs transport failure semantics review

- HTTP outcomes never throw: status-discriminated `{ok,status,data|error,response}` keyed by ACTUAL response (`Response.ok`), frozen wire-form table in `docs/client-error-semantics.md`.
- Transport failures (network/DNS/TLS/abort) reject exactly as plain `fetch` — identity and cause preserved, never wrapped into results, never retried (M3-013 suite).
- Malformed declared JSON throws the single stable `ClientDecodeError` (`LUGAS_CLIENT_010`) with the original response attached.
- Raw/untyped handler responses widen conservatively to `number`/`unknown` branches; unknown media bodies remain unconsumed with the original response readable.
