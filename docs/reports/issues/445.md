# 445 Evidence Report

Issue: [#445](https://github.com/ther12k/lugas/issues/445) (registered 2026-11-24 from the next-development issue pack, draft ID LNR-04). Dispatch: permitted stabilization lane — diagnostic text and test alignment only; no contract semantics change, no public API change.

## Baseline

Branch base: `0d9a946` on main (beta.6 attested docs truth). At base, `tests/unit/diagnostics.test.ts` is 10 pass / 0 fail and `bun run typecheck` is clean — the suite pinned the stale hint, so the drift was invisible to every gate. Base-attested full-suite state: 991 pass / 18 skip / 0 fail (beta.6 packet).

The defect: `src/core/app.ts` maintained `APP_KEYS` (16 accepted keys) while the unknown-key diagnostic hint at the throw site listed only 10 keys (`spa`, `secureHeaders`, `health`, `telemetry`, `compression`, `etag` missing). Two further copies had drifted further: the catalog entry in `src/internal/diagnostics.ts` listed only 8 keys (also missing `logging`, `openapi`), and the catalog golden carried that 8-key variant. A user passing `etag: { … }` misspelled as `eTag` was told the allowed keys as if `etag` did not exist.

## Outcome

The throw-site hint is now derived from the canonical accepted-key set; every other copy is synced to it and a new test fails if any copy drifts again.

- `src/core/app.ts` — added module-level `APP_KEYS_HINT` derived as `` `allowed keys: ${[...APP_KEYS].join(", ")}` `` (Set iteration order = declaration order, stable); the `LUGAS_APP_002` throw now uses it. Code, message, and `context: { key }` are unchanged.
- `src/internal/diagnostics.ts` — the `LUGAS_APP_002` catalog hint is synced to the full 16-key list. It stays a static string (deriving across modules would create an import cycle: `app.ts` imports `diagnostic` from this module), so the new test pins catalog ↔ throw-site equality instead.
- `tests/unit/diagnostics.test.ts` — three changes: (1) the APP-family golden literal updated to the 16-key hint (assertion strictness unchanged — exact equality); (2) new drift alarm: the thrown hint must equal the `DIAGNOSTIC_CATALOG` `LUGAS_APP_002` hint; (3) new loop test: all 16 accepted keys, passed as `{ key: undefined }`, must never produce `LUGAS_APP_002` — a documented key that gets rejected is caught.
- `tests/golden/diagnostics/{catalog,samples}.golden.json` — regenerated with the intentional `scripts/update-goldens.ts --apply` command (2 files, 1 hint line each).
- `docs/diagnostics.md`, `website/src/content/docs/diagnostics.md` — the `LUGAS_APP_002` table rows updated to the derived list; `llms`/agent-docs `--check` gates stay green.
- `docs/reports/issues/M7R1-001.md` quotes an even older hint — historical evidence, intentionally untouched.

## Assumptions

- The catalog hint staying a hand-synced static string is acceptable because the new catalog ↔ throw-site test turns any future drift into a hard failure; removing the duplication entirely would require an import cycle or moving `APP_KEYS` out of `app.ts`, both worse layering.
- Key order in the hint follows `APP_KEYS` declaration order; consumers are expected to treat the hint as prose, not a stable contract (no golden outside the two diagnostics fixtures pins formatting).
