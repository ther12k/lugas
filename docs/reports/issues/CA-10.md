# CA-10 Evidence Report

Implements the owner-directed next roadmap item: serve an already-built
frontend and the typed API from one Bun process, with an explicit
navigation fallback that cannot consume API or asset errors. Scope recorded
through the governance process BEFORE implementation: ADR-0037
(`docs/okf/decisions/0037-spa-hosting.md`, accepted, citing owner direction
2026-09-12) is the successor decision ADR-0018's revisit trigger requires,
and landed as this branch's first commit; this is the second.

## Baseline

Branch base: origin/main `ead6f63` (after CA-9, PR #412). Pre-existing
state: ADR-0018 asset serving (native values, pipeline bypass, explicit
SPA fallback excluded); the #403 truth that static values carry no policy
headers; no deep-navigation story for built SPAs.

## Outcome

1. **`spa: { shell, navigations }`** (new `defineApp` config, `SpaConfig`
   exported): navigations are application-declared exact paths or explicit
   `/*` prefixes (root `/` allowed; no parameters; no catch-all; no
   reserved global prefix). Ownership is fail-closed (`LUGAS_SPA_002`):
   overlap with any declared route, asset mapping/mount, health endpoint,
   OpenAPI endpoint, or another navigation rejects at startup. The shell
   mounts as `{ GET, HEAD }` method maps; facts are manifest-visible.
2. **Policy-capable shell**: a lazy file-backed `Bun.file` handler wrapped
   with logging → secureHeaders → CORS exactly like health endpoints —
   identical security/cache headers at `/` and every deep navigation
   (revalidation default `cache-control: no-cache`). HEAD returns headers
   with no body; every other method falls through to not-found — never a
   successful shell.
3. **Explicitly identified content-hashed assets**: object form of
   `assets.files` (`{ path, cacheControl }`) compiles to a file-backed
   pipeline handler carrying the cache header — policy composition without
   eager in-memory loading. String-form mappings and `dirs` mounts keep
   ADR-0018 semantics bit-for-bit (native, no pipeline headers).
4. **Diagnostics**: `LUGAS_SPA_001` (invalid config), `LUGAS_SPA_002`
   (ownership collision) — union, catalog, `docs/diagnostics.md`, goldens
   regenerated (+12 catalog lines via `scripts/update-goldens.ts --apply`).

### Constraint compliance (review point 4)

No runtime build (shell must exist, `LUGAS_SPA_001`); no eager frontend
buffering (`Bun.file` lazy file-backed responses); no request-path
filesystem scanner and no MIME implementation (exact mappings only; serving
delegated to Bun); Linux-only `dirs` restriction untouched (no directory
walker added).

## Assumptions

- Bun's `/prefix/*` wildcard requires ≥1 further segment, so exact `/app`
  and prefix `/app/*` own disjoint request sets — not an ownership conflict
  (consistent with ADR-0018's `patternsOverlap` semantics); the ownership
  test uses an exact path inside a declared prefix for the collision case.
- CORS composes with `spa` (the shell is a pipeline handler); the blanket
  ADR-0018 `assets`+`cors` rejection is intentionally unchanged for native
  asset values.

## Security considerations

Ownership collisions fail closed before startup; the shell inherits
pipeline policies (a same-policy guarantee native statics never claimed —
documented, not silent); no directory scanning or path-joining surface was
added (hashed assets are exact startup-validated mappings); containment
boundaries of native mounts are unchanged.

## Known limitations / Not exercised

- No ETag/304 for the shell (revalidation refetches; conditional requests
  are a possible amendment).
- OpenAPI/health collision tests cover exact-path endpoints (wildcard
  navigation vs exact endpoint is the realistic shape; wildcard-vs-wildcard
  endpoint collisions cannot occur — endpoints are concrete).
- Performance measurements (API-only vs API-plus-SPA launch/readiness, RSS,
  asset-workload memory) belong to the starter milestone, per the owner's
  sequencing; none are claimed here.
