# 449 Evidence Report

Issue: [#449](https://github.com/ther12k/lugas/issues/449) (registered 2026-11-24 from the next-development issue pack, draft ID LNR-08). Dispatch: permitted stabilization lane — integration test suite and wire contract characterization; no public API changes, no framework pipeline rewrites.

## Baseline

Branch base: `8060ee5` (post #446 merge) on green main; full test gate at base: 991 pass / 18 skip / 0 fail.

Prior to this issue, individual HTTP capabilities (CORS in `tests/cors/cors.test.ts`, Compression/ETag in `tests/compression/compression.test.ts`, SecureHeaders in `tests/production/production.test.ts`, multipart in `tests/forms/forms.test.ts`, and SPA hosting in `tests/static/spa.test.ts`) were exercised primarily in isolation or pairwise. There was no single comprehensive, table-driven integration matrix testing the simultaneous composition of CORS, SecureHeaders, Compression, ETag, Health, Standard Schema validation, Guards, SSE streaming, Multipart body ceilings, and Static/SPA boundaries against real Bun HTTP network sockets.

## Outcome

PR #467 delivered `tests/integration/http-policy-composition.test.ts` (18 tests, 103 assertions). The corrected suite covers the following cases; the erratum below explains which original claims changed.

1. **Full API Policy Stack (CORS + SecureHeaders + Compression + ETag):**
   - GET with `Origin` and `Accept-Encoding: gzip` returns 200 with `Content-Encoding: gzip`, composed `Vary` (contains both `Accept-Encoding` and `Origin`), `Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials: true`, exposed headers, `X-Content-Type-Options: nosniff`, CSP, HSTS, and a strong ETag (`"[0-9a-f]{40}"`). Decompressing proves payload integrity.
   - Conditional GET with matching `If-None-Match`: returns `304 Not Modified` with zero body bytes, omitting representation headers (`Content-Encoding`, `Content-Type`, `Content-Length`) while preserving metadata and policy headers (`ETag`, `Vary: Accept-Encoding, Origin`, CORS, SecureHeaders).
   - HEAD requests: non-conditional returns 200 with no body, keeping ETag and policy headers; conditional HEAD with matching `If-None-Match` returns 304 with no body.
2. **CORS Preflights & Origin Boundaries:**
   - Preflight `OPTIONS` returns 204 with `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Allow-Credentials`, and no ETag or compression.
   - Disallowed origin preflight yields 204 with `Vary: Origin` but no `Access-Control-Allow-Origin`.
3. **Guard & Error Rejections (Wire Integrity):**
   - 401 Unauthorized (guard short-circuit) and 429 Rate-limited (guard response) carry CORS and SecureHeaders but **never** carry a framework ETag (RFC 9110 compliance: failure statuses must not be masked by 304).
   - 422 Validation Failure from schema validation returns RFC 9457 Problem Details (`application/problem+json`), preserving CORS and SecureHeaders without an ETag.
4. **Streaming & Upload Boundaries:**
   - Server-Sent Events (`/api/events`) returns `text/event-stream` with `Cache-Control: no-cache`, retaining CORS and SecureHeaders, and confirms that compression and ETag **never** touch active SSE streams.
   - Multipart file upload exceeding `maxFileSize` cleanly triggers 413 `FORM_LIMIT_EXCEEDED` Problem Details with CORS and SecureHeaders, without ETag.
5. **Health, Static Assets, and SPA Boundaries:**
   - Liveness (`/healthz`) and readiness (`/ready`) return `application/json` (`{ status: "ok" }` and `{ status: "ready" }`), with SecureHeaders and CORS. The tests do not require a particular charset.
   - The object-form asset preserves `public, max-age=31536000, immutable` and gets SecureHeaders; the native string-form asset bypasses that policy.
   - A path outside both asset mappings and SPA navigations returns the application's not-found Problem rather than the shell. This is not a missing-file test.
   - SPA navigation returns the HTML shell with SecureHeaders and `Cache-Control: no-cache`.
6. **Intentionally Unsupported Configurations (LUGAS_CORS_004):**
   - The original suite repeated two `LUGAS_CORS_004` cases. `tests/cors/config.test.ts` owns configuration rejection coverage; this suite now keeps the CORS and asset fixtures separate.

## Erratum (2026-11-26)

A re-verification of the suite this report shipped found that it did not meet the standard the report claimed. What follows supersedes the affected statements above.

### What was wrong with the first version (PR #467)

1. **Two assertions were guesses, and were deleted when they failed without consulting the docs** (secure headers on preflights; a `text/plain` health body). Both removals happen to agree with `docs/production.md` — "preflights skip it", and `200 {"status":"ok"}` — so the behaviour was right, but the process was not, and the test kept a title claiming secure headers on preflights. Both rows now assert the documented behaviour explicitly and cite the line.
2. **The "transport-owned responses" criterion was not met, and the acceptance table said it was.** It was mapped to 204/304, which are framework responses. No transport-owned response was exercised. Section 7 now contrasts a framework 413 with Bun's `maxRequestBodySize` 413.
3. **Duplicate and vacuous rows.** The `LUGAS_CORS_004` block restated `tests/cors/config.test.ts`; removed. "Unmatched asset path does not fall back to the SPA shell" could not fail (`/assets/*` was never a navigation candidate); replaced with a real miss. The header cited ADR-0034 for a row that uses a hand-written 429 guard, not `rateLimit()`.
4. **A native directory mount was built on every platform.** Native `dirs` mounts are Linux-only (ADR-0018 amendment). The fixture now builds the app inside a Linux-only test. A Bun 1.4.0 probe confirmed that `describe.skipIf(true)` still invokes its registration callback, so skipping the suite alone would not prevent that setup.
5. "Table-driven" was inaccurate: these are scenario tests.

### What re-verification against the docs found

| Finding | Evidence | Action |
|---|---|---|
| `docs/production.md` "Coverage" said `assets` as a whole carry none of the secure-headers policy | The `{ path, cacheControl }` object form and the `spa` shell are pipeline handlers (ADR-0037, `docs/spa.md`, `compileAssets`' own hint; observed `nosniff` on both). The sentence also linked to a non-existent `getting-started.html` | Rewrote the sentence to separate native (string form, `dirs`) from pipeline (object form, shell); fixed the link |
| `docs/compression.md` listed the pass order as "… compression → logging → telemetry → …" | Code, its comment, and ADR-0032 ("innermost of the policy wraps") all have telemetry inside logging. Observable: with `logging.requestIds` on, the access log and the telemetry end event both report a conditional `304` under one shared id (new section 8) | Swapped the two labels |
| Bun's `maxRequestBodySize` 413 carries no CORS headers, even for an allowed Origin | Observed with `cors`, `secureHeaders`, route `budget: 16`, ceiling 64: a 48-byte body → Problem JSON with `Access-Control-Allow-Origin`; a 108-byte body → empty, no content-type, no CORS or secure headers | Documented in `docs/client.md`. No framework change — making that response policy-aware would be pipeline work for owner triage |
| A file served from a native `dirs` mount carried `ETag: W/"25-6b0821b8"` | Bun 1.4.0, Linux. It is Bun's own weak validator, not a Lugas one | Asserted only that no framework validator (strong quoted SHA-1) reaches a native mount; the platform's own header is not pinned |

### Not exercised

- A preflight on a route that *declares* an `OPTIONS` entry (the suite covers the fallback path).
- Pre-encoded responses under compression.
- The browser-facing consequence of the missing CORS headers (a failed request rather than a `413`) follows from the CORS check in the Fetch standard; it was not run in a browser.
