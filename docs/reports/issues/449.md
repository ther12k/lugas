## Outcome

Delivered `tests/integration/http-policy-composition.test.ts` (18 tests, 103 assertions), providing an evidence-backed characterization of the full HTTP policy stack:

1. **Full API Policy Stack (CORS + SecureHeaders + Compression + ETag):**
   - GET with `Origin` and `Accept-Encoding: gzip` returns 200 with `Content-Encoding: gzip`, composed `Vary` (contains both `Accept-Encoding` and `Origin`), `Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials: true`, exposed headers, `X-Content-Type-Options: nosniff`, CSP, HSTS, and a strong ETag (`"[0-9a-f]{40}"`). Decompressing proves payload integrity.
   - Conditional GET with matching `If-None-Match`: returns `304 Not Modified` with zero body bytes, omitting representation headers (`Content-Encoding`, `Content-Type`, `Content-Length`) while preserving metadata and policy headers (`ETag`, `Vary: Accept-Encoding, Origin`, CORS, SecureHeaders).
   - HEAD requests: non-conditional returns 200 with no body, keeping ETag and policy headers; conditional HEAD with matching `If-None-Match` returns 304 with no body.
2. **CORS Preflights & Origin Boundaries:**
   - Preflight `OPTIONS` returns 204 with `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Allow-Credentials`, and no ETag or compression.
   - Disallowed origin preflight yields 204 with `Vary: Origin` but no `Access-Control-Allow-Origin`.
3. **Guard & Error Rejections (Wire Integrity):**
   - 401 Unauthorized (guard short-circuit) and 429 Rate-limited (guard response) carry CORS and SecureHeaders but **never** carry a framework ETag (RFC 9110 compliance: failure statuses must not be masked by 304).
   - 422 Validation Failure from schema validation returns RFC 9457 Problem Details (`application/problem+json`), preserving CORS and SecureHeaders without an ETag.
4. **Streaming & Upload Boundaries:**
   - Server-Sent Events (`/api/events`) returns `text/event-stream` with `Cache-Control: no-cache`, retaining CORS and SecureHeaders, and confirms that compression and ETag **never** touch active SSE streams.
   - Multipart file upload exceeding `maxFileSize` cleanly triggers 413 `FORM_LIMIT_EXCEEDED` Problem Details with CORS and SecureHeaders, without ETag.
5. **Health, Static Assets, and SPA Boundaries:**
   - Liveness (`/healthz`) and Readiness (`/ready`) endpoints respond with `application/json; charset=utf-8` (`{ status: "ok" }` and `{ status: "ready" }`), wrapped by SecureHeaders and CORS.
   - Hashed static assets preserve `public, max-age=31536000, immutable` caching and SecureHeaders.
   - Missing static assets return 404 and do not fall back to the SPA shell.
   - SPA navigation returns the HTML shell with SecureHeaders and `Cache-Control: no-cache`.
6. **Intentionally Unsupported Configurations (LUGAS_CORS_004):**
   - Confirms that configuring `cors` with `assets` or with static `Response`/Blob route values fails closed at `defineApp()` with diagnostic `LUGAS_CORS_004`, because static/asset routes bypass the framework response pipeline and cannot enforce CORS policy headers.

## Assumptions & Limitations

- The test server runs on real ephemeral ports (`createTestServer`) through Bun's HTTP engine.
- CORS on preflight requests returns directly from the outer CORS fallback layer with CORS headers, bypassing application response handlers and SecureHeaders by design.
- Combining CORS with static asset configuration remains intentionally unsupported (`LUGAS_CORS_004`) to prevent bypasses on un-policy'd responses.
