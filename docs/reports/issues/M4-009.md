## Assumptions

- **ADR-0017 status disclosure**: the manifest representation these goldens lock is governed by an ADR still marked *proposed*, with owner review scheduled at M4R1-GATE (#204). Locking now is deliberate and reversible: if the gate amends representation, `scripts/update-goldens.ts --apply` regenerates fixtures and the diff is reviewed exactly as designed. This issue does not mark the ADR accepted.
- Only `bunCompatibility` is normalized (observed toolchain version). `frameworkVersion` is a synced build constant and stays literal — a version bump is a real contract change and SHOULD fail goldens until reviewed.
- Diagnostic samples capture REAL throws at wiring sites (not synthetic objects) so catalog↔site binding drift fails the golden too.
- The runner prints the first differing line plus the update command instead of writing files.
