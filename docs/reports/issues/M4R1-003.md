## Assumptions

Recorded before coding:

1. **Guard input gains validated slots.** Every `runGuards()` call site passes `{ request, services, params, query?, headers?, body? }`. Refinement recorded before implementing the call sites: `params` is always present (raw string map when no schema declares one) because Bun always supplies path params and the framework-wide `BaseContext.params` is non-optional; `query`/`headers`/`body` appear exactly when the route declares the corresponding schema. Guards also see prior guards' enrichments (unchanged behavior).
2. **Framework-owned reserved keys expand to six**: `request`, `services`, `params`, `query`, `headers`, `body` — enforced for enrichment regardless of whether the route declares the slot. Existing message substring `cannot overwrite reserved context key '<key>'` is preserved verbatim so merged tests (`tests/integration/guard-enrichment.test.ts`) remain green; a stable code is added on top.
3. **New catalog codes** (family GUARD, next free numbers; codes are frozen API, messages documented):
   - `LUGAS_GUARD_005` — guard returned an invalid result shape (undefined/null/array/Date/primitive/non-plain object). Valid runtime results: native `Response`, plain object (`Object.prototype` or null prototype), or Promise of either.
   - `LUGAS_GUARD_006` — enrichment attempts to overwrite a framework-owned key.
   - `LUGAS_GUARD_007` — duplicate enrichment key across guards; message names both producing guards.
4. **"Plain object" definition** (documented contract): `typeof === "object"`, non-null, non-array, prototype is `Object.prototype` or `null`. Class instances (incl. Date) and Response-like wrappers fail closed under `LUGAS_GUARD_005`. Literal objects carrying keys like `status` remain legal enrichments (indistinguishable from Response-like by shape; documented limitation).
5. **Handler context construction hardening**: framework-owned keys are applied AFTER guard enrichment as a defense-in-depth layer (enrichment rejection remains the primary guarantee). All three pipeline branches plus the async fallback branch get identical ordering.
6. **Sync fast path stays synchronous** — result-shape validation is a synchronous check; existing zero-Promise-allocation test (1k calls) must stay green.
7. **Type-level guard input inference stays out of scope** (owned by M4R1-005/#199); this issue is runtime semantics only. Guard handlers typed loosely keep compiling.
8. **Short-circuit Response behavior unchanged** (native Response short-circuits before enrichment).

## Type/runtime/bundle impact

- Runtime: guards receive validated slots (behavior fix); invalid shapes now fail closed at request time instead of silently passing. Sync fast path unchanged in allocation profile (validated checks are synchronous).
- Types: internal-only; guard handler input cast documented in source (type inference owned by #199).
- Bundle: +~120 lines across pipeline/guards/diagnostics.

## Security considerations

- Closes privilege-escalation vector: a guard could previously overwrite the validated `body` seen by the handler (e.g. inject `role: "admin"`).
- Reserved-key enforcement now covers query/headers/body even when undeclared.
- Diagnostics carry only scalar identity facts (guard name, key) — no payload data.

## Known limitations

- "Plain object" contract rejects class-instance enrichments by design; literal objects carrying keys like `status` remain indistinguishable from Response-like shapes and stay legal (documented in assumptions).
- Type-level inference of enriched guard input remains loose until M4R1-005.
