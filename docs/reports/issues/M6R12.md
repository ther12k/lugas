# M6R12 — Preserve drop outcomes from union-returning toJSON hooks (#325)

## Baseline

- `main@ea2cda5` (post-M6R11 merge, PR #324; #323 closed; #315 open).
- Trigger: follow-up review confirming both M6R11 fixes and finding the last typed-wire defect in the promised drop semantics: **a single `toJSON()` with a union return type containing `undefined` lost the drop branch before classification.** Reproduced before implementation: type probe `[{ value: string }, [string], { value: never }, [never]]` vs runtime truth (`{}`, `[null]`, `{}`).

## Finding verified against the exact tree (confirmed)

`HookOnce<MaybeDropHook>` → `string | undefined`; `JsonifyAfterHook` distributed → `string | never` → `string`. `never` was the drop representation, so the drop branch was erased by union reduction before `MemberDrops`/`JsonifyElement` could see it: the member key stayed required (client could compile `result.data.value.toUpperCase()` while the decoded value was `{}`) and the element lost its `null`. Drop-plus-throw hooks (`toJSON(): undefined | bigint`) collapsed to the throw sentinel (`{ value: never }` / `[never]`) instead of `{}` / `[null]`. The existing tests missed it because `Dropping | string` unions distribute at the member level; here the union appears only *after* the hook, inside one object type.

## Outcome

Drops now have a durable sentinel, mirroring the throw sentinel from M6R10:

- `JsonDrops` — the position serializes to `undefined` (undefined/function/symbol/`void`, or a hook result that is one of those).
- `JsonThrows` — serialization throws (`bigint` at any position, including hook results).
- `JsonifyAfterHook` maps to the sentinels; being distinct union members, they survive union reduction (`never` absorbs into unions; sentinels do not).
- `WireValue<R> = Exclude<R, JsonDrops | JsonThrows>` and `HasDrop<R>` project at the leaves:
  - Members: may-drop + value → **optional** key with the value; drop-only or drop+throw → key removed; no drop + value → required; throw-only → required `never` (unchanged convention).
  - Elements: drop present → `null` included; value present → included; throw-only → `never`.
  - Public root `Jsonify<T>` → `WireValue<JsonifyRaw<T>>`.
- Keyset flags became two-dimensional (`MemberMayDrop`/`MemberHasValue` read from the raw outcome): the old single boolean could not express "sometimes drops, sometimes serializes" for a single non-union member.
- A hook explicitly returning `never` classifies as a throw-signal (`[never]`), not a drop — a never-returning function cannot produce the `undefined` that omission/`null` represent.
- One intentional honest change: an `any`-typed member now resolves optional (`{ any?: any }`) — an `any` value may be `undefined`, so the key is possibly absent (was required under the never-as-drop scheme).
- A hook returning `Date` (or another object) after the hook is serialized as a plain object at that same position — no re-entry — matching the ECMA algorithm; unchanged from M6R10.

## Boundary (accepted per review)

With this correction, the **typed-wire boundary is settled for the beta scope**. The documented prototype/enumerability approximations, cyclic structures, and deferred `problem()` Jsonification are explicit beta limitations (already acknowledged in evidence); they are categorically different from this case, which sat inside the ordinary promised drop semantics.
