# M6R6.1 — Release-evidence integrity corrections (#311)

## Baseline

- `main@b05947a` (post-M6R6 merge, PR #310), verified as the exact tree under review.
- Trigger: independent re-review. All six M6R6 corrections confirmed PASS; source GO; holding the attestation under load 9–14 confirmed correct. One new deterministic P1 release-integrity gap plus three P2s.

## Findings verified against the exact tree (all confirmed)

1. **P1 — stale client bundle evidence.** `scripts/benchmark-client-types.ts` ended `main().catch(console.error)` → exit 0 on any failure (unlike plain/validated runners). Its `results.json`/`smoke.json` carried no commit/Bun/platform/arch binding, and the release gate preferred `smoke.json` checking only `rawBytes ≤ max`. Stale ignored archive + failing client run + `set -e` flow → gate wrapped old bundle bytes into the current candidate's `release-evidence.json`; the builder had no client binding to reject.
2. **P2 — owner shell block not fail-closed.** No `set -euo pipefail`; `npm view lugas version 2>/dev/null  # MUST fail` was a comment, not an assertion. A checksum or `npm whoami` failure would not stop tag+publish; an already-claimed `lugas` name would *pass* the check and only die at `npm publish` — after the tag was pushed.
3. **P2 — platform/arch over-claim.** The gate header claimed archives bind to "the baseline environment platform/arch", but plain env = {bunVersion, cpuModel, commit}, validated env = {bunVersion, commit, timestamp}; `process.platform`/`process.arch` were never recorded, and release validation compared commit only.
4. **P2 — sentinel contradiction.** The builder's manifest covers every non-hidden file in `docs/releases/beta/`; nothing rewrote the DO-NOT-PUBLISH README, so a successful attestation would have checksummed a banner claiming the path was intentionally empty next to the final tarball.
5. **Ledger** — #309 mixed technical attestation with the irreversible owner publication decision.

## Outcome

All five findings fixed on this branch. The attestation remains environment-locked (#309); no step order changed.

- **Client runner** (`scripts/benchmark-client-types.ts`): `import.meta.main` guard + catch sets `process.exitCode = 1`; archive format `lugas-client-benchmark-v2` with `env{commit, bunVersion, platform, arch, cpuModel}` (cpuModel via the same lscpu probe as the plain runner).
- **Plain/validated runners**: env extended with `platform`, `arch`, `cpuModel`, and `loadAverageBefore`/`loadAverageAfter` (plain: before at start / after at archive write; validated: before at main() start / after at summary). Host conditions are now auditable from the archives instead of trusting a narrative.
- **Release gate** (`scripts/check-performance-budget.ts`):
  - client evidence: legacy/unbound format is never consumed (dev: "ignored"; release: FAIL); in release mode requires `env.commit == packageSourceCommit` (or HEAD when unpinned), matching platform/arch, and positive finite bytes ≤ budget;
  - plain/validated archives: release mode now enforces `env.platform === process.platform && env.arch === process.arch` ("cross-machine evidence" FAIL) — the header claim is now true; header updated;
  - `release-evidence.json` gains `environment{platform, arch, cpuModel, bunVersion}` and `loadAverage{before, after}` from the plain archive (additive; format stays `lugas-release-evidence-v2`).
- **Builder** (`scripts/release/build-beta-packet.ts`):
  - checklist bash block: `set -euo pipefail` first; `npm whoami >/dev/null`; explicit assertion aborts with a clear error if the namespace is no longer unclaimed;
  - after the builder-executed verify regenerates evidence, the builder requires the `environment` binding (missing = pre-M6R6.1 evidence → fail) and warns on platform/arch mismatch with the assembly host (legitimate cross-machine two-worktree flow remains possible but is flagged);
  - rewrites the active-path README into an "Attested beta artifact set — owner publication pending" banner (package source, attestation commit, tarball SHA-256) before computing `SHA256SUMS`, so the manifest no longer contains a self-contradictory sentinel.
- **#309 re-scoped (option A)**: closes at clean-checkout checksum PASS; publication remains an explicit owner action. State transitions documented on the issue.

## Assumptions

- `lugas-client-benchmark-v2` archive shape (additive `format` + `env` fields) is acceptable; both `smoke.json` and `results.json` carry identical content.
- Cross-platform mismatch is release-blocking while cpuModel divergence is only a warning: numbers from a different OS/arch class are not attestable, but a different CPU on the same platform/arch can still be audited (recorded) without failing a two-worktree flow.
- Client-runner healthy-run test executes a full `bunx tsc` (the runner measures typecheck cost); bounded by a 180s test timeout and observed at ~10s.
- The client-browser harness fix above is in scope for this branch because `bun run verify` must be green to merge; it is documented as adjacent work with its root cause (verified by stash-reproduction).

## Security considerations

- Closes an evidence-integrity hole of exactly the class M6R1–M6R6 target: not wrong numbers, but numbers possibly not belonging to this candidate.

## Known limitations

- Platform/arch binding cannot distinguish two machines of the same platform/arch; cpuModel + load averages are recorded for human audit (the #309 quiet-host requirement remains a procedure-level condition).
- A full release-mode PASS of the gate is exercised only by the real attestation flow (sandbox tests cannot provide a typecheck binary + tarball + full archive set); the sandboxed tests prove the failure paths.
- The final attestation still has not been executed (#309, environment-locked).
