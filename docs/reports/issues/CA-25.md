# CA-25 — Examples verification hardening

## Baseline

At frozen `134f163`: 16 shipped examples; only `client` had a self-contained
smoke (`EXAMPLE-SMOKE-OK`), `proof-api`/`realworld` had integration tests,
and `spa-starter` had its own 24-test suite with a `verify:modes` parity
check limited to **representative routes** (CA-22 known limitation). The
other 13 examples' README curl checks were manual-only. Owner direction
(2026-09-17): "continue build example"; scope chosen per governance =
harden current examples (bridge milestone stays gated post-0.1.0 by
ODR-0018/roadmap; no bridge code or design in this issue).

## Outcome

- **14 new smoke scripts** (`examples/<name>/smoke.ts` for basic,
  validation, auth, proof-api, realworld, cookies, uploads, compression,
  rate-limit, telemetry, production, websockets, drizzle, static) + one
  shared harness (`examples/smoke-helpers.ts`). Pattern follows the
  `client/smoke.ts` precedent: import the example's exported `app`, serve
  in-process on an ephemeral port (`port: 0`), assert exactly the
  README/source-documented behavior, print `<name>-SMOKE-OK`, stop the
  server. Drizzle is the exception — its server is a self-contained
  walkthrough (serve → self-fetch → graceful shutdown), so its smoke runs
  the real process on a probed free port and asserts stdout + exit 0.
- **Gate coverage** without touching protected files:
  `tests/integration/examples/smoke-all.test.ts` runs all 14 sequentially
  (drizzle uses a fixed port in-process → no parallelism) and requires the
  `-SMOKE-OK` line from each. Wired into the normal `bun test`/`verify`
  collection automatically.
- **`verify:modes` extended to full-contract parity** (closes the CA-22
  "representative routes only" limitation): every AppContract route is now
  compared raw vs `--conditions=lugas-dist` — tasks list/create(422)/201,
  complete (401 + authed 200), delete (authed 204 + unknown-id 404),
  ready, hello, greetings (valid + 422), uploads (multipart), me (401),
  events (first SSE frame), login ({ok:true} + HttpOnly cookie identity;
  token value is random so identity is asserted, not value), SPA shell,
  and `/app/*` fallback. 16 checks total; success line unchanged
  (`MODES-PARITY-OK`).
- **Two genuine example defects found by the new smokes and fixed**
  (adjacent example code, not framework):
  1. `examples/realworld/app.ts` — four dead "not found" branches:
     Bun `sqlite.query().get()` resolves `null` (never `undefined`) and
     drizzle `.all()` resolves `[]` (never `undefined`), so the
     `=== undefined` guards never fired. Symptom: unknown-user login
     crashed to a 500 instead of the documented 404 Problem; PATCH/DELETE
     on a missing id returned 200-ish success instead of 404; a deleted
     user's live session token crashed instead of the documented 401.
     Fixed in all four sites (login row, resolveSession row, PATCH
     `length === 0`, DELETE `length === 0`). The existing
     `tests/integration/realworld.test.ts` never exercised the missing-id
     paths — which is exactly the gap the smokes close.
  2. `examples/drizzle/server.ts` — hardcoded port 3000; now honours
     `PORT` env like every sibling server entry (needed to run the
     walkthrough on busy dev machines).
- `examples/README.md` Test-coverage section rewritten to describe the
  smoke layer, the gate command, and the full-parity scope.

Two assertion-construction errors were corrected during development

`exactOptionalPropertyTypes` optional property). None weakened an
assertion.

## Security considerations

Smoke servers bind ephemeral localhost ports only; the drizzle smoke
probes a free port before spawning its process. No secrets, tokens, or
credentials beyond the examples' own demo constants. The redacted-500
assertion in `telemetry` explicitly checks that the thrown message does
NOT reach the client.

## Known limitations

- `realworld`/`uploads` smokes assert exact seeded/derived values
  (filename-derived MIME types, bus payload shapes); if an example's
  payload changes intentionally, its smoke needs a matching update — same
  discipline as any golden assertion.
- `verify:modes` login parity compares cookie identity (name + HttpOnly)
  rather than token value (random by design); SSE parity compares the
  first frame only (heartbeat/tick cadence is timing-dependent).
- The drizzle smoke depends on the walkthrough's stdout text.
