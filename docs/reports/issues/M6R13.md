# M6R13 — Preserve guard enrichment types when a guard can short-circuit with a Response (#328)

## Baseline

- `main@df35fbe` (post-M6D1 docs restructure), clean tree, `bun run verify` green, 648 tests / 112 files.
- Trigger: external review confirming the guard-union typing gap flagged during the M6D1 survey and classifying it as a beta release blocker: the primary authentication pattern — a guard returning `TypedResponse<401, …> | { user: … }` — left `ctx.user` untypeable, and the committed auth example worked only via `ctx: any`.

## Finding verified against the exact tree (reproduced before implementation)

`GuardContribution` (src/internal/context.ts) checked `Result extends Response` on the naked parameter, so TypeScript **distributed the conditional per union member**: the enrichment member survived but every `Response` member was rewritten to `Record<never, never>`. A guard returning `TypedResponse<401, E> | { user: U }` therefore contributed `{ user: U } | Record<never, never>`; intersected into `RouteContext`, the poisoned union member made `ctx.user` inaccessible (`Property 'user' does not exist on type '(Record<never, never> | { user: … }) & …'`). Async guards fared worse: a `Promise<…>` result was itself an object, so the whole Promise leaked into handler context. Baseline probe run: 15 errors across the eight acceptance scenarios (types `_t1`–`_t2b`, `_t4`–`_t5`, route handlers, `_t6*`).

Probe also confirmed the reviewer's split was only half-broken: `ExtractGuardResponse`/`ExtractGuardEnrichment` (src/core/types.ts) already distribute union members correctly, so guard short-circuit statuses (401/403) were already present in `AppContract` and the typed-client status union — revealed directly (`{ status: 201 | 401; … }` on the union-guarded route) and now pinned by regression coverage. No change was needed (or made) in src/core/types.ts.

## Outcome

`GuardContribution` now extracts the enrichment from the resolved non-response branch:

```ts
Exclude<Awaited<Result>, Response> extends infer Enrichment
  ? [Enrichment] extends [never] ? Record<never, never> : Enrichment extends object ? Enrichment : Record<never, never>
  : Record<never, never>
```

- `Exclude<…, Response>` distributes over the result union and removes every Response-compatible member (`TypedResponse` structurally extends `Response`), leaving exactly the enrichment — no poisoned `Record<never, never>` union member.
- `Awaited` resolves `Promise<Response | { user }>` and per-branch sync/async mixes (`TypedResponse | Promise<{ user }>`) to the same contribution.
- Response-only guards (`TypedResponse<401, …>`, raw `Response`) resolve to `never` and fall through to `Record<never, never>` — the whole contribution, never a union member, so response-only guard context stays clean.
- Compile-time only; zero runtime change (the type is not in any runtime path; manifest, bundle, and diagnostics bytes unchanged).
