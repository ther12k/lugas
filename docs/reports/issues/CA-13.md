# CA-13 Evidence Report

Owner review of #415 (2026-09-12), finding 2: `scripts/verify.ts:68–79`
examined `LUGAS_PERF_RELEASE` INSIDE the archive-exists condition, so
release verification with no plain archive recorded perf-gate SKIP and
verify could exit 0 — weaker than the intended contract. The underlying
`check-performance-budget.ts` already fails closed on missing/stale
evidence in `--release` mode; the wrapper simply never asked.

## Outcome

- `scripts/perf-gate-plan.ts` (new): `resolvePerfGatePlan({ release,
  hasPlainArchive })` — run `--release` whenever release mode is requested;
  run development-mode checks when an archive exists; SKIP only in
  development mode with no archive. Truth table documented at the module.
- `scripts/verify.ts`: the perf section now consumes the plan (checker
  invoked on `release || hasPlainArchive`). No other step changed.

## Pinned outcomes (tests/unit/verify-perf-gate.test.ts)

| Condition | Pinned result |
|---|---|
| development, no archives | plan SKIP with documented reason |
| release, no archives | plan runs `--release`; checker sandbox (results/ empty) exits NONZERO with "release mode fails closed" |
| release, stale archives | checker-level pins already in `tests/unit/perf-gate-integrity.test.ts` (release rejects foreign/stale archives — 10/10 green) |
| release, current complete evidence | plan runs `--release`; actual checks decide (integrity suite pins PASS/FAIL semantics) |

The decision lives in a pure module because `verify.ts` executes
`process.exit(await main())` at import — the wrapper itself is not
unit-importable without running the whole suite.
