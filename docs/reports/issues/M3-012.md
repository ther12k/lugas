## Assumptions

- Decode policy choice: **throw** rather than result-carried marker. Rationale (documented in the semantics doc): malformed declared JSON is a contract violation from a nonconforming server, not an HTTP outcome — it must not masquerade as a payload; throwing keeps happy-path payloads exactly as declared while `.response` preserves full manual access.
- The declared content type is authoritative when a nonconforming server sends mismatched bytes (JSON under `text/plain` stays a string); this keeps one rule instead of sniffing.
- Bodiless statuses (`204`, `205`, `304`) skip parsing even when a content type is present — acceptance requires 204 specifically; 205/304 included as the same class.
- Redirect handling relies on fetch auto-follow; manually surfaced redirects classify by their real status. No opaque-redirect simulation (browser-only construct) — recorded as limitation.
- Error messages embed status/media only, never body content, extending the established redaction guarantee.
