## Outcome

`websocket(config)` — a new route value kind implementing the ADR-0028 contract:

- **Upgrade decision through the ordinary compiled pipeline.** The descriptor compiles to a synthetic route whose pipeline handler IS the upgrade decision: `before` guards run first (a short-circuit `Response` rejects the handshake with that response — verified 401), `params`/`query`/`headers` schemas validate pre-upgrade (`422` Problem Details verified), the ADR-0020 traffic gate holds upgrades during service `init`, and the error policy redacts throws.
- **Native sockets, unwrapped.** `open`/`message`/`close`/`drain` receive Bun's `ServerWebSocket` plus the descriptor-derived context (services, validated slots, ordered guard enrichment — typed via the same `RouteContext` derivation as routes; enrichment verified end-to-end). `message` is required; LUGAS_WS_001 rejects unknown keys and malformed guards at declaration time.
- **Honest rejection:** non-upgrade requests to a websocket route return `426 Upgrade Required` Problem Details (verified live), never a hang.
- **Multiplexing:** one Bun `websocket` handler per server dispatches per route through the upgrade `data` key (two concurrent routes verified). A user-supplied `serve({ websocket })` option alongside declared ws routes fails closed (`LUGAS_WS_002`).
- **Shutdown semantics:** `lugasLifecycle.shutdown()` closes every tracked socket with `1001 "server shutting down"` before the drain deadline; route `close` handlers run; the client observes the close frame (verified).
- **Manifest:** websocket routes appear as ordinary `lugas` route facts (path/method/guards/validates) — `lugas-manifest-v1` unchanged.

## Assumptions

- Bun ignores the fetch/route return value after a successful `upgrade()`, so the pipeline's Response contract is satisfied with an unsent `204`; access logs record `204` for upgrade requests (documented in `docs/websockets.md`).
- `ws.data` is framework-namespaced (`__lugasRoute`/`__lugasContext`); applications never read it.
- `close()` on an already-closed socket during shutdown is best-effort (try/catch in `closeAll`) — shutdown never crashes on socket races.
- Socket-level observability (connection counts, message rates) is application-owned; the upgrade request logs once through the standard access log.

## Security considerations

- Origin checking on handshakes cannot be CORS (Web platform truth); `docs/websockets.md` ships the same-origin guard recipe — browser-facing sockets must adopt it.
- Guard/validated decisions happen before the handshake, so unauthenticated sockets never open (no window where a socket is open but unauthorized).
- Shutdown close-1001 gives clients a machine-readable reason to reconnect-with-backoff instead of leaking half-open sockets.
- No socket data, headers, or context values enter diagnostics (config-shape codes only, key names as scalar context).

## Known limitations / Not exercised

- `ws.publish`/`subscribe` pub/sub is Bun-native and unopinionated — not wrapped, therefore not separately tested beyond socket passthrough.
- Custom `serve()` fetch override + websocket routes: the fetch fallback never sees upgraded requests; untested combination (routes still upgrade via the compiled map).
- Per-socket message schemas (JSON codec) deliberately out of scope (ADR-0028 alternatives; revisit trigger recorded).
