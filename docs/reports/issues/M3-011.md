## Assumptions

- Runtime branch is exactly `Response.ok` (200–299 success); 3xx surfacing at the client would classify as failure per fetch semantics — documented, untested against real redirects (fetch follows them transparently).
- Compile-time narrowing uses literal template matching (`\`${S}\` extends \`2${string}\``) over the M3-003/M3-004 outcome unions; widened `number` statuses stay open as either branch with `unknown` payloads so raw handler Responses remain safely typed.
- Media policy interim until M3-012 freezes semantics: recognized JSON/problem/text parse from a clone; unknown media are not consumed; absent content-types and 204/205/304 yield `undefined`; malformed JSON currently yields `undefined` payload with the original response attached rather than throwing.
- The escape hatch intentionally still returns the raw `Response`.
- One documented generic boundary (`TResult` cast inside private `send`) connects runtime-truth parsing with compile-time result types; every public signature remains cast-free.

## Type/runtime/bundle impact

- Public method return type changes from `Promise<Response>` to `Promise<ClientCallResult<…>>` — the M3 milestone's central contract step; escape hatch unchanged.
- Compile-time cost: one extra conditional layer over existing outcome unions (no whole-contract redistribution).
- Browser bundle grows by parser (~1 KB).

## Security considerations

- No secrets or header values enter diagnostics (parsing adds no messages beyond prior issues).
- Unknown media bodies are never speculatively consumed or logged.

## Known limitations

- Malformed declared JSON currently yields `undefined` payloads; throw-vs-result freeze belongs to M3-012.
- 3xx classification follows `Response.ok` if ever surfaced directly.
- Clone-based parsing doubles transient memory for recognized media types (bounded by body size).
