# CA-12 Evidence Report (evidence-and-withdrawal record)

Disposition (owner review, 2026-09-13): the 2 500 ms budget is **kept
unchanged**; the v3 proposal (2500→4000 ms) is **withdrawn** and
`benchmarks/baselines/m5-accepted.json` is restored to v2 verbatim. This
report is an evidence record, not a budget proposal. It separates what was
measured from what may be concluded, corrects two record defects found in
owner review (median method, procedure description), documents the exact
source identities measured, and carries a dated attribution amendment
(2026-09-13): the source of the concurrent host load during the recorded
samples is unconfirmed.

The original justification for raising the budget — "the current tree is
slower because of scope growth" — was not supported by the paired
comparison and is withdrawn. Nothing here replaces it with an unconditional
"no compiler regression" claim: quiet-host performance was not measured and
remains the prerequisite for any future budget decision.

## Procedure (as actually executed)

`scripts/typecheck-comparison.ts`: interleaved round-robin cells —
(earlier, current, earlier, current) per round × 5 rounds, a 750 ms settle
before every invocation — giving **ten timed samples per cell per
workload**, not five as an earlier revision of this record claimed.
Diagnostics collected in separate runs (`--extendedDiagnostics`,
`--listFilesOnly`), per-sample `/proc/loadavg` snapshots recorded.
Full-repo runs use each revision's own tsconfig; the fixture is ONE
identical file (`consumer-fixture.ts`, sha256 `440a2b70…6990`) using only
APIs present at both revisions, compiled with a pinned flag set mirroring
the repo tsconfig minus DOM. Verified identical dependency state:
TypeScript 7.0.2, @types/bun 1.4.0, zod 4.4.3, unchanged bun.lock.

**External-load disclosure (attribution amended 2026-09-13)**: concurrent
host load was observed during the recorded samples (load ~15–20 per
sample). The report originally attributed that load to a
`ga-m6-soak-72h` soak workload, but that attribution was not
independently established. A subsequent host inspection (2026-09-13
09:08 WIB) found no active matching soak workload. The historical source
of the contention remains unconfirmed. The measurements remain
exploratory, and their disposition is unchanged.

## Interpretation (narrow)

1. The sampled **full-repository runs were faster** at the current source
   and produced fewer compiler types and instantiations. The observed
   slowdown that motivated v3 (3.37–3.65 s on the main checkout) is
   consistent with concurrent-load inflation (source unconfirmed — see the
   amended disclosure) rather than added checking work.
2. The fixed consumer produced **more instantiations (+5.8 %) and higher
   observed wall times (+80 ms median)** at the current source. Because
   the experiment ran under concurrent load, the quiet-host performance
   and the practical significance of this difference remain unresolved.
   The hypothesis that the additional instantiations come from the
   stronger client contracts (framework failure branches in outcome
   unions) is plausible but was not isolated by this experiment.
3. Interleaving **reduces ordering bias**; it does not guarantee
   equivalent CPU contention, frequency, or scheduling per invocation, so
   the paired deltas under load are exploratory until a quiet-host run
   confirms them.
4. Fewer instantiations are useful **diagnostic evidence**, not a complete
   measure of compiler cost. The cause of the 23.8 % instantiation DROP is
   observed but unidentified: the `HeaderSeed` hypothesis was tested on
   7fe452f and refuted (+15 instantiations, recorded as a negative
   result); a bisect across the merge range remains optional follow-up.

This is enough to **withdraw** the original justification for 4 000 ms. It
is not enough to establish "no compiler regression" or any budget change.
The existing measurement policy already requires quiet-host evidence for
budget decisions; that requirement stands.

## Budget decision and plan

- v3 WITHDRAWN; v2 baseline (2 500 ms) retained verbatim; this PR changes
  no threshold.
- **The measurement window is condition-based (amended 2026-09-13).** The
  earlier "wait for the soak to end, ≥ 2026-09-15 21:25 WIB" anchor was
  derived from the unconfirmed soak attribution and is withdrawn; that
  timestamp is not an independent release requirement. A manual
  host-readiness check against the documented quiet-host conditions
  (`docs/performance-gates.md`; operationally: load 1-min < 2.0 AND
  15-min < 3.0, and no other significant load such as a process > 30 %
  CPU) may happen at any time. Measurement begins only when ALL documented
  conditions actually hold — not merely because load is declining or a
  process-name search finds nothing — and its scope is narrow: freeze the
  exact source and environment, collect the five `tsc --noEmit` samples,
  run the actual single-shot gate on identical inputs, then STOP and
  record the disposition. The release checklist is not entered
  automatically; it resumes only after the results are dispositioned.
- If quiet median ≤ 2500 ms: no baseline change; the main-checkout
  perf-gate returns green with v2 intact. Note the documented gate is a
  separate single-shot check — a passing calibration median does not by
  itself guarantee a passing gate; run the actual gate against the quiet
  evidence.
- If quiet median > 2500 ms: a NEW proposal with clean five-run evidence,
  using this record as the attribution starting point.
- Operational status at recording time: functional/type checks passing;
  development verification without archives can pass with a documented
  performance SKIP; the main-checkout performance check under current load
  FAILS; current-candidate release performance acceptance is PENDING.
  Raising the budget is explicitly not the remedy being pursued — the next
  performance decision belongs to a correctly measured quiet-host run.
