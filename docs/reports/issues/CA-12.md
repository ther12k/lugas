# CA-12 Evidence Report — typecheck budget v3 (PROPOSED, owner review required)

**This PR is not self-merged.** `benchmarks/baselines/m5-accepted.json` states
"Baseline updates require PR review", and the prior raise (v2, 2026-09-11)
followed that process. Raising a failing budget is exactly the action the
repository's prohibited-shortcuts list guards, so this branch carries the
re-measured evidence and stops at review.

## Situation

- The verify perf-gate was SKIP in every worktree run because the archive it
  needs (`benchmarks/results/`) is UNTRACKED and exists only in the main
  checkout (dated 2026-09-09 — before this session). Main's verify therefore
  RUNS the gate — and currently FAILS it: `typecheck 3757ms > budget 2500ms`.
- The checked tree grew through the v2 calibration point (M5-era → M9-008 →
  this session's RF-1/RF-3/multipart/SPA-hosting batteries and their test
  suites). Steady state on quiet system at `fcdf5ec`:
  `tsc --noEmit` 3.42 / 3.65 / 3.42 / 3.37 / 3.43 s — **median 3.42 s**, well
  past the 2500 ms budget. Scope growth, not a runtime regression: the
  framework's throughput and bundle budgets pass unchanged (plain-static
  69538 rps, plain-json 61621 rps, validated-post 47639 rps, client bundle
  14900 B — all at or above target).

## Proposal (v3)

- `typecheckBudgetMs` 2500 → **4000** — mirrors v2's ~14% headroom over the
  re-measured median (3.42 s median → 4000 ms ≈ 14–17% headroom).
- `environment.commit` → `fcdf5ec`; `version` → 3; v3 note appended to
  `notes` recording the five runs and the same "scope growth, not a
  regression" rationale v2 used.
- Everything else unchanged: throughput thresholds, client bundle cap,
  binding status.

## Validation

With the v3 baseline and main's real archives:

```
✓ plain-static / plain-json / validated-post / client bundle — unchanged, pass
✓ typecheck 3151ms ≤ budget 4000ms
PASS: 0 blocking failure(s), 0 alert(s)
```

The checker's own in-gate typecheck measurement (3151 ms, warm) sits below
even the old-plus-nothing; the standalone five-run series above is the
conservative record.

## Alternatives

- Leave main red: unacceptable — a red verify gate normalizes ignoring the gate.
- Shrink the checked tree (test splitting/project references): worthwhile
  engineering, but it changes the repo's type structure and cannot land as a
  budget-relief substitute; recorded as the follow-up that could eventually
  bring the median back under a future re-tightening.
- Owner may instead reject v3 and set a different number — the evidence above
  supports any value ≥ ~3.7 s with v2's headroom discipline.

## Known limitations / Not exercised

- Single host (the baseline host: i5-13420H, 15.36 GB, Linux x64, Bun 1.4.0)
  — same discipline as v2's re-measurement.
- CI runners may measure differently; the budget binds wherever the gate runs.

## Dependency / merge notes

- Independent of all merged work; based on origin/main `fcdf5ec`. Merging
  this PR is the owner's review decision; until then main's verify fails the
  perf-gate step on the main checkout only (worktrees skip — no archives).
