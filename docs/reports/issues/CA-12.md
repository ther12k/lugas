# CA-12 Evidence Report (amended per owner review of #415)

Owner review decision (2026-09-13): request changes — the 4000 ms number may
be plausible, but "scope growth, not a regression" was not established; a
paired comparison (full repository AND one identical consumer fixture at
7fe452f vs fcdf5ec, with compiler diagnostics) was required before any
budget recommendation. This amendment performs that comparison, reports the
result — which REFUTES the premise of the original v3 proposal — and
withdraws the threshold change.

## What the paired comparison found

Procedure (`scripts/typecheck-comparison.ts`, committed): interleaved
cells (A,B,A,B,… × 5 rounds — alternation cancels uniform external load
drift; sequential cells are order-biased), five timed runs per cell per
workload, diagnostics collected in separate runs (`--extendedDiagnostics`,
`--listFilesOnly`), per-run load snapshots recorded. Full-repo runs use
each revision's own tsconfig; the fixture is ONE identical file
(`consumer-fixture.ts`) using only APIs present at both revisions,
compiled with a pinned flag set mirroring the repo tsconfig minus DOM.
Verified identical dependency state: TypeScript 7.0.2, @types/bun 1.4.0,
zod 4.4.3, unchanged bun.lock, same 87-file standard-library resolution.

**External-load disclosure**: the owner's `ga-m6-soak-72h` benchmark
(started 2026-09-12 21:25 WIB, runs until ~2026-09-15 21:25 WIB) was
executing throughout (load ~15–20 recorded per run). Absolute medians are
load-inflated vs v2's quiet-host calibration; the interleaved design keeps
the PAIRED deltas valid under uniform load.

| Measure (median of 10 interleaved runs) | 7fe452f | fcdf5ec | Δ |
|---|---|---|---|
| Full repository wall time | 2 876 ms | 2 451 ms | **−14.8 %** |
| Full-repo types (deterministic) | 491 137 | 359 115 | **−26.9 %** |
| Full-repo instantiations (deterministic) | 2 187 950 | 1 667 139 | **−23.8 %** |
| Fixed consumer wall time | 272 ms | 351 ms | +29 % (noisy; one 884 ms outlier) |
| Fixed-consumer instantiations (deterministic) | 58 070 | 61 413 | +5.8 % |

## Attribution conclusions (per the owner's decision rule)

1. **"The full repository gets slower" is REFUTED.** Under matched load the
   current tree typechecks ~15 % FASTER in wall time, with 24 % less
   compiler instantiation work and 27 % fewer live types (deterministic
   counters, reproducible). The earlier absolute readings that motivated
   v3 (3.37–3.65 s on the main checkout) were inflated by the 72 h soak.
2. **The fixed consumer is NOT materially slower.** Wall time moved +29 %
   on a ~0.3 s measurement (noise-sensitive; single 884 ms outlier), while
   the deterministic work measure is +5.8 % instantiations — the expected,
   bounded cost of the stronger client contracts (framework failure
   branches in the outcome unions). Recorded as a small explicit
   developer-experience tradeoff to keep an eye on, not a regression.
3. **Cause of the 24 % instantiation DROP: observed, not yet attributed.**
   The first hypothesis (CA-11's `HeaderSeed` typing change in
   `response.ts`) was TESTED by applying that single change to 7fe452f:
   instantiations moved +15 (nothing) — REFUTED and recorded as a negative
   result. The drop is real (deterministic across runs, identical lib/dep
   file sets — normalized `--listFilesOnly` diffs are empty outside the 18
   added repo files) but its source-level cause is unidentified; identifying
   it is optional follow-up work, not a budget prerequisite.
4. **Consequence for the budget**: the v3 proposal (2500→4000) is
   **WITHDRAWN** — its premise fails the decision rule, and no quiet-host
   measurement of the current tree exists (the soak blocks one until
   ~2026-09-15 21:25 WIB). `benchmarks/baselines/m5-accepted.json` is
   restored to v2 verbatim. The plausible outcome is that the CURRENT tree
   passes 2500 ms quietly (it compiles measurably less work than 7fe452f,
   which calibrated at 2.19 s) — but that must be SHOWN, not assumed.

## Plan (recommended)

1. After the soak ends (≥ 2026-09-15 21:25 WIB): five timed
   `tsc --noEmit` runs at the then-current HEAD on the quiet baseline host
   (same procedure as v2).
2. If quiet median ≤ 2500 ms: no baseline change; main's perf-gate returns
   green with v2 intact (it only runs on the main checkout, where the
   untracked archives live).
3. If quiet median > 2500 ms: a NEW proposal with the clean five-run
   evidence, using this comparison as the attribution record.
