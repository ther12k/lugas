## Assumptions

- Diagnostic code plan (stable identifiers): `LUGAS_CLIENT_001` missing/undefined/null parameter, `002` extra undeclared key, `003` invalid value or non-object params, `004` ambiguous duplicate declaration, `005` invalid template shape. Codes mirror the server-side invariants of `src/internal/path.ts` (params are full segments matching `[A-Za-z0-9_]+`, at most once each; `*` final only).
- "Ambiguous params" interpreted as duplicate `:name` declarations in one template → `LUGAS_CLIENT_004`.
- Wildcard input contract: value is a string (split on `/`) or array of segments; every segment is `encodeURIComponent`-encoded and joined with `/`. Empty rest produces the trailing-slash form `/prefix/`, which Bun matches; bare `/prefix` does not.
- The M0-006 Bun characterization recorded wildcard behavior as partial/unexecuted, so this issue re-probed Bun 1.4.0 directly (probes recorded below) and encodes the findings as executable fixtures rather than relying on stale claims.
- Numbers/booleans are accepted for normal params at runtime (string-coerced); TypeScript callers are restricted to `string` by `PathParams`.

## Implementation

- Template parsing validates shape once and memoizes per literal template string; interpolation walks segments and substitutes each declared name exactly once.
- Normal params: `encodeURIComponent(String(value))` — `/ ? # %` cannot create segments, queries, or fragments.
- Wildcard: per-segment encoding preserves multi-segment intent while preventing query/fragment escapes.
- Errors are plain thrown `ClientPathError`s raised during URL construction, before transport invocation.

## Type/runtime/bundle impact

- Canonical method signatures gain an optional second `input` argument; paths declaring `:name` now require `params` at compile time (previously compile-impossible to supply).
- `ClientMethod` generic change required restoring an explicit cast in one M3-007 test line (union-of-generic-signatures is not callable).
- Browser bundle of `create-client.ts` grows to ~3 KB including path module; zero dependencies.

## Security considerations

- Segment-scoped encoding blocks path-traversal-by-reserved-character, query injection, and fragment injection for normal params.
- Dot-segments ("..") are unreserved and cannot be neutralized by encoding; Bun normalizes them before routing (probed), so a traversal-looking rest resolves against the fallback rather than escaping the site. Recorded as fixture + limitation.
- All validation errors throw before any network dispatch; no silent fallbacks.

## Known limitations

- Wildcard capture is not exposed through `req.params` on Bun 1.4.0; server handlers must read the rest from the request pathname. Client-side contract only controls the built URL.
- Mid-segment colons in static segments are treated as static text (mirrors core validation).
- The escape hatch intentionally performs no interpolation or param validation.
