# M6R1-010 Evidence — Reject the unsupported ALL method key

## Baseline
- Base commit: `3f52b25` (main, M6R1-002 merged)
- Issue: #265 (M6R1-010)
- Bun/TypeScript: 1.4.0 / 7.0.2, Linux x64

## Outcome

Completed. `prepareApp` no longer exempts `ALL` from method-key validation.
Declaring `{ ALL: route(...) }` (or `{ ALL: fn }`) now throws the stable
`LUGAS_ROUTES_002` diagnostic at `defineApp()`/`prepareApp()` time instead of
crashing later with Bun's raw `TypeError: 'routes' expects a Record<...>` at
`serve()` time. The diagnostic hint no longer recommends `ALL`; it directs to
explicit method declaration and states there is no `ALL` key.

## Background
Bun 1.4.0 method maps accept only GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS.
The any-method form (descriptor/function/Response placed directly at the
path) remains the supported catch-all shorthand.

## Files changed
- `src/internal/prepared-app.ts` — owned: `ALL` removed from the exemption; hint corrected.
- `tests/unit/all-method-key.test.ts` — owned (new): rejection tests (code, name, hint).

## Security considerations
Earlier failure with a raw Bun TypeError is a denial-of-diagnostic issue, not
an exploitable path; rejecting at declaration time gives operators a stable,
searchable error.
