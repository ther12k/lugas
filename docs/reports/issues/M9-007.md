## Outcome

Two independent opt-in `defineApp()` config keys in one new internal module (`src/internal/compression.ts`):

- **`compression: true | { encodings?, minSize?, types? }`** — Accept-Encoding negotiation over pipeline responses using only native codecs (gzip/deflate; default both, 1024-byte minSize, standard compressible set + `text/*` + `application/*+json` always matching). Q-values respected (`q=0` excludes, highest preference wins — verified deflate-over-gzip at 0.9-vs-0.5); no usable encoding → identity passthrough. Structural skips, each observable: bodyless statuses, existing `Content-Encoding` (never double-encoded — verified byte round-trip), `text/event-stream` (SSE untouched — verified), `Content-Range`, non-compressible types (verified with octet-stream), and ≤ minSize bodies. `Vary: Accept-Encoding` is appended on every compressible-type response while enabled (compressed or not).
- **`etag: true | { weak? }`** — strong-by-default SHA-1 validators (`"40-hex"`, `W/"…"` when weak — verified form) computed over the **uncompressed** body of GET/HEAD responses; encoding-independence verified (same etag on the gzip-encoded and identity responses). `If-None-Match` per RFC 9110 — exact token, comma list, and `*` all verified → **304** with the same `ETag` and empty body; POST carries no framework etag (verified); application-set etags win (fill-if-absent — verified). The 304 short-circuit runs **before** compression (verified: conditional hit with `accept-encoding: gzip` carries no `content-encoding`).
- **Pass placement:** etag innermost of the two, both inside logging/telemetry (ADR-0033 order); skipped responses cross the chain byte-identical. Composes with `secureHeaders` on one response (verified: content-encoding + etag + nosniff together).
- **Diagnostics:** `LUGAS_COMPRESSION_001` (unknown encodings incl. `"br"`, empty arrays, negative minSize, bad types) and `LUGAS_ETAG_001` (non-boolean weak, non-object) — union + catalog; goldens regenerated (+2 rows, reason recorded here).

## Assumptions

- Bun's `fetch` transparently sends `accept-encoding: gzip` and auto-decompresses — tests assert the wire encoding via the header and consistency via the transparently-decoded body (noted in test comments); byte-level wire proof came from the live curl example (3,514 → 103 bytes).
- Compression buffers compressible bodies synchronously within the skip rules — bounded by what the handler already produced (the Lugas response norm); SSE is structurally excluded.
- SHA-1 is a validator (collision-resistance unnecessary for etags, RFC 9110 §8.8.3 permits it); it is not used for security anywhere.
- Etag wraps only pipeline function handlers; native/static values bypass the pipeline and gain no validators (same truth as secureHeaders/CORS).
- `Vary` is appended (not replaced) so handler-set vary values survive.

## Security considerations

- Compression operates only after the structural skips; pre-encoded responses are passed through (no oracular re-encoding that could strip application-chosen encodings).
- CRIME/BREACH class attacks target compressed secrets — Lugas compresses only response bodies the application produced; no secret-mixing occurs at the framework layer. Applications combining secrets with attacker-influenced content in one compressible response accept the standard risk (documented context, not framework policy).
- Etag hashes body bytes only; no header/payload data enters diagnostics.
- 304 responses are constructed with a bare header set (ETag only) — no accidental leakage of the original response's headers.

## Known limitations / Not exercised

- `deflate` (zlib) negotiated responses were verified by header selection, not byte round-trip (Bun fetch transparently decodes gzip only; deflate decode path asserted via selection + identity-equivalence of the shared encode pipeline).
- No `Last-Modified`/`If-Modified-Since` (ADR-0033 alternative-rejected); no brotli (native absence, revisit trigger recorded).
- HEAD requests reach the wrap as the GET handler's response; Bun drops the body afterward — compression on HEAD encodes bytes the transport discards; acceptable (documented), a `request.method === "HEAD"` skip is a candidate tightening.
