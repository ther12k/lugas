## Outcome

Two independent opt-in `defineApp()` config keys implementing the ADR-0029 contract (one new pure module, `src/internal/production.ts`):

- **`secureHeaders: true | { contentSecurityPolicy?, hstsMaxAge? }`** — conservative, fill-if-absent policy on every pipeline response. Defaults: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`. CSP is strictly opt-in (an explicit string; never generated — owner constraint). HSTS opt-in via `hstsMaxAge`. A handler's own header wins (fill-if-absent verified: `sameorigin` override preserved while the policy fills the rest). Invalid config fails closed (`LUGAS_HEADERS_001`). Coverage: route responses, guard short-circuits, framework errors, and the not-found fallback (serve.ts wraps the fallback path). Static values and assets bypass the pipeline and carry none (documented). Applied inside the CORS wrap, so `cors` composes unchanged (verified with allow-origin + policy on one response).
- **`health: true | { livenessPath?, readinessPath? }`** — defaults `GET /health` and `GET /ready`, mounted as ordinary compiled routes (manifest facts present; verified) but **outside the traffic gate** — that boundary is the liveness/readiness distinction:
  - `/health` answers `200 {"status":"ok"}` during service init while ordinary routes are held 503 (verified with a blocked init service).
  - `/ready` answers synchronously — `503 {"status":"unavailable"}` while init is pending or after a startup failure (verified), `200 {"status":"ready"}` once every init settles (verified flip). Readiness never hangs: a `settled` flag on the traffic gate (kept in sync by serveApp against the real init promise) lets the handler answer without awaiting.
  - Path renames verified; collisions with routes or assets fail closed (`LUGAS_HEALTH_002`); invalid paths/`true`-form violations fail (`LUGAS_HEALTH_001`).
- **Non-goals honored:** no per-dependency probes (ADR-0026 revisit trigger stands), no CSP builder, no `X-XSS-Protection`, no runtime health-state API.
- **Diagnostics:** `LUGAS_HEADERS_001`, `LUGAS_HEALTH_001`, `LUGAS_HEALTH_002` — union + catalog; goldens regenerated (+3 rows, reason recorded here).

## Assumptions

- Fill-if-absent (handler wins) is the documented contract: the policy hardens negligence rather than fighting intent (ADR-0029 Alternatives records the framework-wins rejection).
- Readiness answers 503 synchronously while init is pending — an orchestrator polling gets an answer every probe; the flip to 200 is eventually consistent with gate settlement (sub-microsecond after resolution via the flag's microtask update).
- Health endpoints log through the standard access log when `logging` is configured (consistent with openapi endpoints).
- `LUGAS_HEALTH_002` also covers health-vs-health self-collision implicitly (`LUGAS_HEALTH_001` rejects identical paths earlier).

## Security considerations

- The baseline cannot regress per-route: policy applies to guard short-circuits and framework errors too, not only happy-path handler returns.
- Fill-if-absent is documented (not hidden): a handler that explicitly sets a header overrides the policy — accepted tradeoff recorded in ADR-0029.
- No CSP is invented; applications that set one emit exactly their string (byte-verified in tests).
- `/health` availability during startup is intentional (a booting process is alive); `/ready` is the traffic signal. Neither exposes service names, versions, or internals — bodies are fixed one-key JSON.
- Health endpoints are ownership-checked at startup, so they cannot silently shadow or be shadowed by application routes.

## Known limitations / Not exercised

- Static values (`Response`, `Bun.file`, `{ dir }`) and assets bypass the pipeline and carry no policy headers (documented; same truth as CORS/guards).
- Policy headers are not applied to websocket upgrade responses (the handshake `204` is discarded by Bun) — socket-level policy is the application's.
- HSTS value is `max-age=<n>` only; `includeSubDomains`/`preload` directives would be an additive config follow-up if evidence demands.
