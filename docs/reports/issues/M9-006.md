## Outcome

`defineApp({ telemetry: { onRequestStart?, onRequestEnd? } })` — dependency-free request events (ADR-0032):

- **Two scalar-only events.** `request.start` (method, path, route, requestId when `logging.requestIds` is on) and `request.end` (+status, durationMs, errorClass: `"guard"` for 401/403, `"framework"` for 400/413/415/422, `"not-found"` for 404, `"handler"` otherwise incl. redacted 500s). Redaction by construction — a dedicated test asserts authorization/cookie/query secret values never appear in events.
- **One identity source:** telemetry wraps INSIDE the logging wrap, mints the request id when `requestIds` is on, stamps `x-request-id` on the response, and the logging wrap now prefers an existing header value over minting its own (verified: events' id === header id). Unmatched requests report `route: "-"` (access-log convention).
- **Request-end = drain boundary.** `request.end` fires when the response exists AND work registered through `lugasLifecycle.track(task, request)` settled — the request object is the correlation token (a per-app WeakMap; no globals, no AsyncLocalStorage). Verified: response delivered while end event correctly withheld until the tracked task resolves. `track()`'s public type gains the optional `request` param (additive); uncorrelated track calls still drain at shutdown unchanged.
- **OTel recipe application-owned:** `docs/telemetry.md` ships the span-mapping recipe; the test suite drives a span-recording adapter. `@opentelemetry/api` added as a **devDependency only** (test/example — the ADR-0026 drizzle-orm pattern); zero runtime dependencies (package rehearsal untouched by design — the dependency is dev-only).
- **Not-found fallback covered:** the serve-time fallback emits events via its own wrap (route `-`, errorClass `not-found` — verified).
- **Diagnostics:** `LUGAS_TELEMETRY_001` (non-function callbacks, unknown keys) — union + catalog; goldens regenerated (+1 row, reason recorded here).

## Assumptions

- The telemetry wrap sits inside logging so the id stamping is visible to the access log; start events fire at pipeline entry (after the logging wrap starts, before guards) — duration measured from there.
- `errorClass` is derived from the response status (the framework's own error statuses are distinguishable by code); a custom `onError` returning 4xx still classifies as `handler` — documented behavior, not heuristic mind-reading.
- Correlation uses the request object identity; a cloned request (e.g. `new Request(url, request)`) is a different identity — the ADR's plain-token contract.
- The devDependency does not affect the package rehearsal: rehearsals stage `git archive HEAD` and the export map/runtime imports are unchanged; `@opentelemetry/api` appears in no runtime file.

## Security considerations

- Scalar-only events with a dedicated redaction test — hostile headers/cookies/query cannot leak into telemetry sinks.
- No payload-derived fields: `errorClass` is a four-value enum, never error text.
- The correlation WeakMap holds no request data beyond scalar facts and cannot outlive requests.

## Known limitations / Not exercised

- No child spans around guard execution or service init (ADR-0032 revisit trigger).
- `errorClass` derives from status codes; applications with custom semantics can classify in their own reducer.
- The recipe's span-handle passing is application-solved (the doc shows the pattern); the framework deliberately ships no span registry.
