# M6R7 — Contract boundary honesty (#314)

## Baseline

- `main@c73aa17` (post-M6R6-ATT merge, PR #313; #309 closed with all acceptance boxes ticked).

## Findings verified against the exact tree (all confirmed)

1. **P1 — `AppContract` not publicly exported; README example cannot compile.** `README.md` line 81 instructs `import type { AppContract } from "lugas"`, but `src/index.ts` exported no contract type. The types live in `src/core/contract.ts`. The M6 rehearsal missed this because its consumer used a fixed contract without generics; in-repo type tests import `src/` directly, bypassing the package boundary.
2. **P2 — client request slots typed from schema OUTPUT.** `src/core/contract.ts` `RouteInputContract` mapped every schema slot through `StandardSchemaOutput` (`src/core/contract.ts:22-25` at baseline). The client sends the wire shape (schema **input**); only the handler context sees the validated **output**. For `z.string().transform(s => s.length)` the client demanded `number` where the wire carries `string`. `StandardSchemaInput` already existed (`src/internal/standard-schema.ts:40`).
3. **P2 — `json()` response typing not serialization-honest.** `json<S, B>(status, body: B): TypedResponse<S, B>` preserved exact `B` while the runtime runs `JSON.stringify`: `Date` claimed `Date` on the client (wire: ISO string), always-`undefined`/function/symbol keys silently vanish, `Map`/`Set` serialize to `{}`, `bigint` throws.
4. **P2 (new, discovered by the review-mandated test; pre-existing on c73aa17) — module-only apps lost client path restriction.** `defineApp` types `TRoutes` with a `Readonly<Record<string, unknown>>` default (constraint at `src/core/app.ts:43`). For apps built only from `modules`, that index signature reached `AppContract`, whose key remap (`as string & Path`) preserved it, so `PathsForMethod` collapsed to `string` and **any path typechecked** at client call sites. The in-repo path-restriction test only covers inline-`routes` apps (`tests/types/client-methods.test-d.ts`), so it never caught this — and the README's own quickstart app is module-based. Root cause chain verified by reveal probes: inference through the branded `LugasApp<any, infer TRoutes>` slot collapses the module literals to the bare index signature, while the `routes` property type still carries them.

## Outcome

All four findings fixed. Zero runtime behavior change — every fix is compile-time or export-surface only.

- **Public exports** (`src/index.ts`): re-export `AppContract`, `FlattenPathMethods`, `RouteContract`, `RouteInputContract` from `./core/contract` and `Jsonify` from `./core/response`. `Jsonify` joins the root surface because it now appears inside public signatures (`TypedResponse<S, Jsonify<B>>`) and wrapper authors need the name.
- **Wire input** (`src/core/contract.ts`): `RouteInputContract` slots use `StandardSchemaInput`; handler-context typing elsewhere is untouched (`StandardSchemaOutput` stays where validation output is the fact). Path params remain template-derived.
- **Serialization honesty** (`src/core/response.ts`): new exported `Jsonify<T>` type and `json()` now returns `TypedResponse<S, Jsonify<B>>`. Semantics: `toJSON()` results are unwrapped (`Date` → `string`); values that are always `undefined`/`Function`/`symbol` (and `void`) drop their keys; possibly-`undefined` members keep the key carrying `undefined` (an absent key reads `undefined` on the client); array elements typed `undefined` arrive as `null`; `Map`/`Set` → `Record<string, never>`; `bigint` → `never` (stringify throws; no usable value is promised); arrays/tuples map homomorphically (tuple length and readonly-ness preserved); optional-property modifiers preserved; `unknown`/`any` pass through unchanged (any-trap first branch).
- **Literal-path contract** (`src/core/contract.ts`): `AppContract` keeps the `LugasApp` brand gate but extracts paths via direct `routes` property inference (the branded slot loses module literals — reveal-probed) and filters index-signature keys (`as string extends Path ? never : string & Path`).
- **Docs**: `src/client/types.ts` query/headers/body doc comments corrected from "schema output type" to wire input; no README change needed (the package was wrong, not the README).
- **Re-attestation consequence**: the attested set (`0b79f09`) is superseded by this merge. M6R7-ATT tracks the re-attestation of the new candidate before publication is reconsidered.

### Design decisions

- **Restriction (`B extends JsonValue`) evaluated and rejected** for finding 3: TypeScript gives implicit index signatures only to fresh object literals, so every handler passing a prebuilt body variable (`json(200, body)` — used throughout the repo's own tests) would break with false positives, while `JSON.stringify` accepts those bodies. Mapping through `Jsonify` keeps runtime permissiveness and models the wire truth instead.
- **Jsonify approximations (documented in the type's doc comment):** prototype-getter-only classes are modeled through their own property types (own-enumerable approximation); tuple elements typed `undefined` become `null` per element, matching element-wise stringify; top-level `undefined` bodies are typed `never` (`empty()` is the honest helper there).
- **`problem()` intentionally not Jsonified** in this wave: its `ProblemFields` extension members are already documented as caller-bounded (`Record<string, unknown>`), and M2-009 governs that surface. Deferred as a consistency follow-up, not silently skipped.

## Known limitations

- `Jsonify` models own-enumerable data; classes exposing values through prototype getters are typed via their declared property types (a documented approximation, consistent with structural typing).
- Apps whose `routes` are supplied as a genuinely index-signature-typed `Record` variable now get an empty compile-time client contract — honest (no literal path facts exist in such a type); the `request` escape hatch remains for those callers.
- `problem()` bodies are not `Jsonified` (see Design decisions).
- The consumer test compiles types only; an installed-tarball runtime round-trip smoke remains a deferred idea (the runtime is exercised by 626 in-repo tests against the same source that ships).
