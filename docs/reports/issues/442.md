# 442 Evidence Report — decision record and candidate prep

Issue: [#442](https://github.com/ther12k/lugas/issues/442) (LNR-01, owner gate). This report records the owner decisions taken on 2026-11-28 and the candidate-prep work executed under them. It does **not** close the gate: tag movement, publication, and the final GO/HOLD remain separate explicit owner approvals.

## Owner decisions (2026-11-28, recorded in chat, transcribed here)

1. **Candidate identity: successor `0.1.0-beta.7` cut from `main`** — chosen over qualifying the existing attested beta.6 bytes. Rationale recorded in the decision: the attested `8de2da4` bytes carry the known-wrong `LUGAS_APP_002` hint (#445's fix lists all 16 accepted keys; the attested bytes list 10), tested-code ≠ released-code (23 commits behind at decision time), and the perf evidence chain is already muddled across `134f163`/`8de2da4` (see #443). A successor makes tested code the released code.
2. **Platform disposition (`assets.dirs` / openat2 containment): document the kernel floor, no source change.** `openat2(RESOLVE_IN_ROOT)` was introduced in Linux 5.6 (Linux man-pages — the historical "Linux ≥ 5.0" claim in the parked PR #439 discussion is factually wrong; committed repo docs already said 5.6). On kernels < 5.6 containment is not guaranteed (the maintainer-reported exposure was never reproduced). The supported contract is **Linux ≥ 5.6**; the existing `LUGAS_ASSET_004` non-Linux rejection stays; **runtime capability enforcement is a tracked revisit trigger**, not implemented in this change.

## What was deliberately NOT done here

- **The package rehearsal WAS run, but its artifacts are retained untracked, not committed.** The rehearsal stages from `git archive HEAD` (this branch, post-bump) and produced `lugas-0.1.0-beta.7.tgz` plus the regenerated attestation files (`SHA256SUMS`, `inventory.json`, `sbom.json`, `provenance.json`, `package-rehearsal.json`). Committing them now would leave the committed set knowingly inconsistent — regenerated rehearsal files describing beta.7 next to a `release-evidence.json` that still describes beta.6, written before the required quiet-host release gate has run. So: the tarball and artifacts are captured to the untracked retention directory (`lugas-comparison/beta7-candidate-20261128/`), the tracked attestation files are restored to their committed beta.6 state, and the packet builder rebinds everything to beta.7 in one consistent pass **after** the release gate. The rehearsal result and tarball digest are quoted below as candidate-prep evidence, not qualification evidence.
- **No tag, no publish, no dist-tag change.** Separate owner approvals, per M6-010/M6-GATE and the LR2-01 acceptance criteria.
- The exact-artifact consumer lane (`installed-consumers.test.ts`) still targets the committed beta.6 tarball by default — correct, since beta.6 remains the only *attested* artifact. It will be repointed to the beta.7 tarball + checksum when the beta.7 packet is committed.
