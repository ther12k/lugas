## Assumptions

- Value policy (documented in module header): scalars are `string | number | boolean`, stringified once; arrays serialize as repeated keys; empty array omits the key (matching decoder absence); `null`, nested objects/arrays, and non-scalar elements throw `LUGAS_CLIENT_006` before fetch.
- "Preserve existing base URL path/query according to one tested rule" is implemented as `appendQuery`: non-empty query strings append with `?`, or `&` when the target already carries a query; existing queries are never clobbered or re-encoded. Base URLs cannot contribute legacy queries because M3-006 rejects them at creation.
- Query compile-time typing follows M3-002's established derivation (schema output type); consequently `z.default()` fields are required client-side even though the server would default them. Recorded as a known typing quirk pending integrator review.
- The escape hatch remains raw passthrough (no serialization), consistent with M3-007/M3-008 semantics.

## Implementation notes

- `serializeQuery` deliberately accepts `unknown`: it is the runtime enforcement point of the query policy, while compile-time safety lives in `MethodCallInput`. The object-narrowing cast occurs only after runtime validation (object, non-null, non-array).
- No CSV joining, no JSON embedding, no implicit number/boolean/date coercion anywhere.
- Integration fixtures exposed one genuine contract consequence: wire format cannot distinguish `[x]` from `x`, so per M2-004's frozen decode semantics a single-element array arrives as a plain string. Encoded as an explicit fixture using a union schema rather than silently weakened.

## Type/runtime/bundle impact

- Canonical method input gains an optional typed `query` field required exactly when the route declares a query schema.
- Client browser bundle grows by the query module (~1 KB); zero dependencies; `URLSearchParams` is platform-native.

## Security considerations

- Encode-once prevents double-encoding bugs and parameter-smuggling via pre-encoded separators.
- Object/array-of-array rejection blocks prototype-style payloads and silent data shaping.
- Prototype-pollution defense stays server-side in the null-prototype decoder (M2-004); the client adds no global lookups.

## Known limitations

- Single-element arrays are wire-indistinguishable from scalars (frozen M2-004 semantics); schemas expecting arrays must tolerate the scalar shape or callers must send ≥2 elements. Explicit fixture documents the behavior.
- Query typing uses schema output types per M3-002, so defaulted fields are required client-side.
- The escape hatch performs no query serialization.
