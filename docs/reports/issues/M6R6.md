## Findings verified against the exact tree (all confirmed)

1. **Stale artifact set in the active publication path.** `docs/releases/beta/` still held `lugas-0.1.0-beta.1.tgz` (sha256 `347f11c2…`), `inventory.json` (69 entries, no NOTICE), `provenance.json` (sourceCommit `d2a07b2…`), `sbom.json`, `RELEASE_PACKET.md` (69 files, "M6R4 canonical", pre-M6R5 metrics), `CHECKLIST.md` (publish-first, candidate `34439dc…`, "15/15"), `SHA256SUMS`, `evidence-index.md` — all indistinguishable from final artifacts.
2. **Documented attestation order could never succeed.** The release gate writes untracked `docs/releases/beta/release-evidence.json`; the rehearsal refuses any non-empty `git status --porcelain` (`scripts/release/package-beta.ts:74-90`) → deterministic exit on the documented order. Additionally the gate hashes whatever tarball exists at gate time while the rehearsal later rewrites it (`rmSync`+`cpSync`, `package-beta.ts:243-245`) → the builder's three-way hash check is unsatisfiable in both branches (stale tarball → mismatch; absent tarball → evidence `tarballSha256: null` → rejected).
3. **Checklist `cd` bug.** Template emitted `cd docs/releases/beta; sha256sum --check SHA256SUMS; cd ../..` — from `docs/releases/beta`, `cd ../..` lands in `docs/`, so the following `npm publish ./docs/releases/beta/…` resolved `<root>/docs/docs/…` and would fail after the tag was already pushed.
4. **`attestationCommit` recorded but never verified.** The builder typed the field but compared only `packageSourceCommit`; evidence produced on a different commit was reusable, and the packet printed an unproven "Attestation Commit".
5. **Checklist pre-checked PASS before proof.** Builder wrote `[x]` for repository verification / typecheck / compatibility / clean-room while the documented procedure ran `bun run verify` *after* the builder.
6. **Ledger/gate contradiction.** 0 open issues while required work remained → standing blocker registered as #309 (M6R6-ATT).

## Outcome

All six findings fixed on this branch; publication remains HOLD pending #309.

- **Quarantine:** the eight stale files moved (`git mv`) to `docs/releases/history/m6r3/` with a frozen-record README (provenance, tarball hash, entry count, why kept). `SHA256SUMS` still verifies inside that directory (all seven covered files moved together). `docs/releases/beta/` now contains only a DO-NOT-PUBLISH README; no publishable-looking artifact exists in the active path until M6R6-ATT completes.
- **Procedure order corrected** in `docs/reports/gates/M6.md`: M6R5 procedure block marked SUPERSEDED with the reason; new M6R6 addendum documents the executable order (benchmarks → rehearsal on a clean tree → `LUGAS_PERF_RELEASE=1 bun run verify` so the release gate hashes the FINAL rehearsal tarball → builder last) plus an explicit two-worktree variant for `packageSourceCommit ≠ attestationCommit`.
- **Builder hardening** (`scripts/release/build-beta-packet.ts`):
  - fails closed unless `evidence.attestationCommit === ` assembly HEAD — checked before verification and again on the evidence regenerated by the builder-executed verify;
  - executes the full gate itself (`bun run verify` with `LUGAS_PERF_RELEASE=1` and `LUGAS_PACKAGE_SOURCE_SHA` set) BEFORE writing any packet file, refusing to run without benchmark archives; re-reads and re-proves the regenerated evidence (format, both commit bindings, `blockingFailures`/`alerts` zero, tarball hash vs actual bytes) before any output is written;
  - checklist now marks only builder-proven claims (verify/typecheck/perf/rehearsal/clean-room/owner-decision files/legal files/tarball triple-hash); Compatibility-matrix green and no-open-P0/P1 are explicit **unchecked owner items**; header lists both `packageSourceCommit` (tag target) and `attestationCommit`;
  - checksum preflight is a subshell `( cd docs/releases/beta && sha256sum --check SHA256SUMS )` — owner cwd never changes;
  - governance-file presence (ODR-0001/0002, LICENSE, NOTICE, SECURITY.md, GOVERNANCE.md) is checked, not assumed;
  - packet evidence index: canonical pointers are now `release-evidence.json` + `package-rehearsal.json` + M6 addenda; prior report bundles demoted to history; stale "(M6R3)" era references removed;
  - header usage block and fail messages state the required command order.
- **Ledger:** #308 (this wave) and #309 (M6R6-ATT, the only issue allowed to remain open until attestation) registered; no dedupe conflicts (last prior issue was #294; M6R3–M6R5 were tracked via PRs #305–#307).
