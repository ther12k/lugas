# M7R1-001 Evidence Report

## Baseline

- Base commit: `f1fcdc288266fbdbc603ad39e71f971e5589ff3b` (main after PR #336; clean tree).
- Bun `1.4.0`, TypeScript `7.0.2`, Linux x86-64.

## Outcome

Wording-only diagnostic correction. `defineApp()` has accepted the `assets`
config key since M7-001 (PR #335), and `docs/diagnostics.md` already listed
`assets` in the `LUGAS_APP_002` hint row, but the thrown diagnostic hint and
the runtime catalog entry still omitted it. A developer passing a mistyped
asset key saw a hint naming a stale key set.

- `src/core/app.ts` — `LUGAS_APP_002` hint now reads
  `allowed keys: services, routes, modules, assets, notFound, onError`.
- `src/internal/diagnostics.ts` — catalog entry for `LUGAS_APP_002` updated to
  the same hint.
- `tests/unit/diagnostics.test.ts` — expected hint updated.
- `tests/golden/diagnostics/catalog.golden.json`,
  `tests/golden/diagnostics/samples.golden.json` — regenerated with
  `bun run scripts/update-goldens.ts --apply` (reason recorded here per the
  golden-regeneration policy).

No enforcement change: `assets` was already in `APP_KEYS` and accepted; only
the diagnostic text changed. `docs/diagnostics.md` required no change (already
correct — the drift was runtime-behind-docs).
