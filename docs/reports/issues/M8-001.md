## Outcome

`defineApp({ cors })` implements the ADR-0022 policy:

- **Compiled policy:** `src/internal/cors.ts` validates configuration once
  (`compileCorsPolicy`) into a frozen `CompiledCorsPolicy`; preparation and
  serving never re-read user configuration.
- **Compile-boundary enforcement:** `prepareApp` walks the compiled route map
  and wraps every handler function with `corsWrapHandler` (outermost layer —
  outside the traffic gate and error policy, so held 503s and error 500s
  carry the policy). `serveApp` wraps the effective fetch fallback (user
  `fetch` or the not-found policy) with `corsWrapFallback`. No routes are
  synthesized; preflights matching no declared `OPTIONS`/any-method entry
  reach the fallback through Bun's own routing.
- **Fail-closed header posture:** every configured response gets `Vary:
  Origin` (merged, never duplicated); denied/absent origins get no
  `Access-Control-*`; wildcard+credentials is rejected at startup
  (`LUGAS_CORS_003`) and a wildcard callback result under credentials is
  denied at runtime.
- **Preflights:** `OPTIONS` + `Access-Control-Request-Method` answered `204`
  before user handlers; allowed → echo + `Allow-Methods` (default
  `GET, HEAD, POST, PUT, PATCH, DELETE` or the configured set) +
  `Allow-Headers` (default reflection, or strict gating when configured) +
  opt-in `Max-Age`; denied → `204` with `Vary:
  Origin, Access-Control-Request-Method, Access-Control-Request-Headers`
  only. Plain `OPTIONS` passes through with headers applied.
- **Pipeline-bypass rejection (`LUGAS_CORS_004`):** `cors` with static
  `Response`, `Bun.file`/`Blob`, `{ dir }`, or `assets` fails closed at
  `defineApp()`.
- **Diagnostics:** `LUGAS_CORS_001`–`004` registered in the frozen catalog
  (`src/internal/diagnostics.ts`); `LUGAS_APP_002` allowed-keys hint gained
  the previously missing `bodyBudget` plus `cors`.
- **Types:** `CorsConfig`, `CorsOriginDecision`, `CorsOriginInput` exported
  type-only from `src/index.ts` (the ODR-0007 protected-file authority; no
  runtime exports added, `package.json`/`bun.lock` untouched).

## Assumptions

- The preflight `Allow-Methods` answer reflects the configured/default method
  set, not the target route's own methods (the fallback has no path context
  without reimplementing routing). ADR-0022 records this as an accepted
  precision tradeoff; authorization is unaffected.
- Bun 1.4.0 does not enforce the fetch spec's immutable-headers guard
  (verified by probe: append on `Response.redirect()` and received responses
  mutates observably). The wrapper still probes and reconstructs on silent
  no-op so a future stricter Bun cannot silently drop CORS headers.
- `HEAD` is auto-derived by Bun from `GET` method maps and flows through the
  wrapped `GET` handler (pinned by test).
- An empty-string callback origin decision denies (no meaningful origin to
  echo) rather than throwing mid-request.

## Security considerations

- Deny-by-default: absent `cors` emits nothing; configured deny emits no
  authorization headers. `Vary: Origin` is structural on every configured
  response including errors, not-found, denies, and startup-gate 503s.
- Credentials/wildcard incompatibility enforced at startup *and* at runtime
  for callback results (fail closed to deny, never emit an unusable pair).
- No configuration or origin value is echoed into diagnostics; context stays
  scalar (`path`, `method`, `kind`, `key`). Origin strings from requests are
  only ever echoed into `Access-Control-Allow-Origin` after an exact-match or
  callback decision — never logged.
- The `LUGAS_CORS_004` rejection prevents silent partial enforcement on
  pipeline-bypass values; the failure names the route and kind.

## Known limitations / Not exercised

- Real-browser CORS execution is not in CI (matches the recorded
  compatibility boundary: real browsers are not part of the per-OS matrix);
  behavior is pinned at the HTTP level with header-exact assertions.
- Preflight precision limitation (method set, not per-route) as recorded in
  ADR-0022.
- `Private-Network-Access` preflight (`Access-Control-Request-Private-Network`)
  is neither reflected nor answered; the unknown request header is ignored
  and Chrome's PNA preflight would fail. Deferred.
