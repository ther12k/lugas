## Outcome

Existing delegated body-limit behavior is now discoverable and pinned:

- `SafeServeOptions` declares `maxRequestBodySize?: number` explicitly (documented field; forwarded to `Bun.serve` via the existing spread — no enforcement change).
- `tests/security/body-limits.test.ts` rewritten as classified fixtures, each expectation tied to what the fixture sends. Prior loose `[400, 413, 500]` assertion replaced **only** for the well-formed oversized fixture that demonstrably produces a bare `413`.
- `docs/body-limits.md` documents the named option, the observed transport rejection (bare `413`, empty body, inclusive boundary, header-independent byte counting, no handler execution, outside the Lugas Problem Details envelope), and the distinct malformed-JSON `400` class. Scope note added: ADR-0019 budgets are excluded from this issue per ODR-0003.

Empirical pins (probed before writing fixtures, Bun 1.4.0): body of exactly `maxRequestBodySize` bytes → 200 (inclusive boundary); larger → bare `413` empty body; streamed chunked bodies without `Content-Length` counted by consumed bytes (over → `413`, under → 200); rejected requests never invoke the handler.
