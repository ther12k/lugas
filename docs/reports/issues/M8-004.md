## Outcome

`defineApp({ openapi })` implements the ADR-0025 contract:

- **Canonical OpenAPI 3.1 document** generated at `defineApp()` time from the prepared graph facts (paths, methods, module tags) plus declared schemas; served as JSON at `openapi.path` (default `/openapi.json`).
- **Route metadata:** `route({ openapi })` accepts `summary`, `description`, `operationId`, `tags`, `deprecated`, explicit `params`/`query`/`headers`/`body`/`responses` schema overrides. The metadata block is inert unless the app also enables `openapi`.
- **Standard JSON Schema feature detection:** a validator exposing `~standard.jsonSchema()` has its JSON Schema used verbatim; validators without a representation document **presence only** (parameter requiredness from declared position; body as `type: object`) — never a guessed shape.
- **Problem Details component:** the RFC 9457 error envelope (`application/problem+json`) is registered as `#/components/schemas/ProblemDetails` and documented as every operation's default error response.
- **Scalar UI (opt-in, zero-dependency):** an HTML shell at `ui.path` (default `/docs`, or `ui: true`) embedding `data-url` of the document path and loading `@scalar/api-reference` from its public CDN. OpenAPI JSON stays canonical; the UI is replaceable.
- **Framework-native endpoints:** the document and UI handlers are compiled like any handler — they flow through the traffic gate, error policy, logging wrapper, and CORS wrapper; they appear in the manifest as ordinary route facts; `HEAD` derives from `GET`.
- **Conflict rejection:** `openapi.path`/`ui.path` colliding with an existing route or `assets.files` mapping fails closed at `defineApp()` (`LUGAS_OPENAPI_002`); self-collision between document and UI paths is `LUGAS_OPENAPI_001`.
- **Diagnostics:** `LUGAS_OPENAPI_001` (config shape: unknown keys, missing/blank title or version, non-`/` paths, invalid `ui` shape) and `LUGAS_OPENAPI_002` (path collisions) registered in the frozen catalog; goldens regenerated.
- **Exports:** `OpenApiConfig`, `OpenApiDocumentInfo`, `OpenApiRouteMetadata`, `OpenApiUiConfig`, `CompiledOpenApi` (types) from `src/index.ts` per ODR-0009 authority. `package.json`/`bun.lock` untouched — Scalar ships as a CDN reference, not a dependency.

## Assumptions

- The document is generated once at `defineApp()` time (frozen routing graph), not per request: the JSON body is a constant string — routing is snapshotted by contract, so nothing served can drift from the compiled graph.
- `~standard.jsonSchema` is feature-detected via `in` + callability, never by vendor string (ADR-0025 neutrality rule); a throwing `jsonSchema()` degrades to presence-only rather than failing startup.
- Path parameters without explicit schema documentation default to `type: "string"` (the wire-true shape: Bun delivers params as strings).
- The UI default (`ui: true` → `/docs`) matches the roadmap's development-default guidance; exposing it in production remains the application's explicit choice.
- Wildcard (`*`) route facts are not documented as concrete operations — an any-method entry has no enumerable method set at the contract level.

## Security considerations

- The document reflects only what the application declares — no runtime request data, no origin auto-detection, no server addresses unless supplied in `document`.
- UI exposure is explicit (`ui` is opt-in); the shell loads Scalar's script from the public CDN, which is a third-party runtime fetch — documented in `docs/openapi.md` so production deployments can gate or self-host it (replaceable by design).
- Endpoint conflicts fail closed: an application cannot accidentally shadow the document path with a route (or vice versa) — ownership is unambiguous at startup.

## Known limitations / Not exercised

- Response schemas are documented only from explicit `responses` metadata or as schema-less `200`/`default` descriptions; handler return types are a compile-time system and are not introspected at runtime (ADR-0014 separation).
- Multi-server deployment manifests, security schemes (auth), and example values arrive via `document` passthrough (any additional OpenAPI `info`/root fields flow through verbatim) but have no dedicated validation.
- A real-browser render check of the Scalar shell is not in CI (matches the recorded compatibility boundary); the shell is pinned at the HTML level.
- `HEAD` on the document/UI endpoints is auto-derived by Bun from the wrapped `GET` handlers and was not separately asserted.
