## Outcome

The release tarball now carries a prebuilt, browser-executable ESM artifact of `lugas/client`, and both ADR-0021 browser stages executed for real.

**Artifact and specifier (ODR-0004 §2 authority):**

- Build: `scripts/release/build-browser-client.ts` — `Bun.build` of `src/client/index.ts`, `target: "browser"`, `format: "esm"`, unminified, fixed output name `build/lugas-client.esm.js`. Also runnable as `bun run build:browser-client`.
- Export specifier chosen: **`lugas/client/browser`** — a single additional subpath (`"default": "./build/lugas-client.esm.js"`, no `types` condition). Rationale: keeps the client surface grouped under `/client`, statically searchable, zero change to `.`/`./client`/`./testing`, no export conditions to reason about. `.ts` sources remain the only type source of truth; no `.d.ts` fork.
- `files` gained `build`; `build/` is gitignored in the source tree and generated in the staged package copy immediately before `npm pack` (release rehearsal Stage 1b and every mirrored test staging), so committed sources and shipped bytes can never drift.

**Release pipeline (`scripts/release/package-beta.ts`):**

- Stage 1b builds the artifact into the staged copy; new checks: artifact built, artifact present in packed tarball, artifact present in the installed tree, installed export map equals `{".", "./client", "./client/browser", "./testing"}`, artifact executes under Node (fetch stub, no bundler, no Bun global).
- Inventory gained `generatedArtifacts` (path, bytes, sha256, entrypoint, target, format); SBOM gained `generatedComponents` with the artifact sha256 and builder identity.

**Two-stage browser evidence (`tests/browser/`, ADR-0021 §4):**

- Zero-dependency CDP driver (`tests/browser/cdp.ts`): launches the local Chromium-family browser headless, connects to the DevTools WebSocket, evaluates one async expression per page. No automation dependency enters the package, the repo dependency graph, or bun.lock.
- **Stage one** (`stage-one.test.ts` + `fixtures/stage-one.html`): plain-JS, no-bundler page over ordinary `fetch` against a live Lugas server — browser-to-server evidence. Observed in Chrome 152: 200 JSON success; declared 409 with `application/problem+json`; 500 redacted end-to-end (the thrown secret `boom-secret` never reached the page); 204 empty; abort → `AbortError`; closed-port fetch → raw `TypeError`.
- **Stage two** (`stage-two.test.ts` + `fixtures/stage-two.html`): the tarball is packed with the artifact and installed into an unrelated temporary directory; the page imports `/lugas-client.esm.js`, which the app serves (native asset mount) from `node_modules/lugas/build/lugas-client.esm.js` **inside that install**. Observed in Chrome 152: artifact served with `text/javascript` MIME; `createClient` from the installed artifact returns the typed result shapes for 200 / 409 / 500 (no secret leak) / 204 (`data === undefined`); abort → `AbortError`; injected failing transport → raw `TypeError`. The page uses no TypeScript configuration, and the source checkout is outside the consumer's resolution path (`bun install --no-save <tgz>` into a fresh temp dir).
- Type-checking independence (`type-independence.test.ts`): a plain-JS `// @ts-check` consumer with its **own tsconfig** (`allowJs`/`checkJs`/`strict`, `types: ["bun"]` mirrored offline from the repo toolchain) type-checks against the installed package, including a typed `result.data.hello`; negative control proves the harness fails (TS2322). The repository tsconfig never participates.
- Artifact checks (`artifact.test.ts`): two builds from the same sources produce **identical sha256** (reproducibility); the shipped bytes contain no `node:` imports, `Bun.` globals, `bun` imports, `defineApp`, or `src/core` references (graph check on the artifact itself, not just sources); artifact runs standalone under Node.

**Capability model:** suites skip cleanly when npm or a browser binary is absent (documented skip, mirroring the npm-gated consumer suites); `LUGAS_REQUIRE_BROWSER=1` turns a missing browser into a failure so a lane that claims coverage cannot satisfy itself silently.

## Security considerations

- The artifact is generated, not hand-maintained; its sha256 is recorded into inventory/SBOM and bound to the staged sources by the rehearsal provenance (same pipeline that attests the tarball).
- Same-origin lane only; docs state explicitly there is no CORS or browser-matrix claim.
- No new runtime dependencies; the CDP driver is test-only and launches a local binary — no network egress beyond the local loopback server.

## Known limitations / Not exercised

- Safari/Firefox not exercised; the lane does not claim a browser matrix.
- The per-OS compatibility matrix does not execute browser stages; on browser-less machines the suites skip (with `LUGAS_REQUIRE_BROWSER=1` as the enforcement hook for future CI lanes).
- Stage-two drives the client through the artifact for the documented case matrix; visual/bundled-frontend browser flows remain out of scope.
