## Outcome

Completed (tooling) / environment-locked (final attestation run):

1. **Two-identity attestation model** — the impossible self-referential
   invariant (a file cannot contain its own commit hash) is replaced:
   - `packageSourceCommit`: tree the tarball was built from, pinned via
     `--package-source-sha` / `LUGAS_PACKAGE_SOURCE_SHA`.
   - `attestationCommit`: HEAD where the gate/builder run.
   - Evidence format `lugas-release-evidence-v2` records both; release-mode
     archive binding checks the package source when pinned.
2. **Rehearsal result is machine-readable** — `package-rehearsal.json`
   (format `lugas-package-rehearsal-v1`) records packageSourceCommit,
   tarball sha256, checksPassed/checksTotal, entryCount, NOTICE/LICENSE
   presence, dry-run publish result.
3. **Builder is cross-artifact fail-closed** — validates evidence format/
   completeness/source-binding, rehearsal completeness/source-binding, actual
   tarball hash against BOTH evidence and rehearsal hashes, provenance
   sourceCommit and `publishedToRegistry:false`, inventory count and
   LICENSE/NOTICE/README presence, SBOM identity and zero-dep flag, zero
   blocking failures AND zero alerts. All packet figures templated from
   evidence (per-scenario overhead from recorded raw-bun comparators — fixes
   the validated-post/plain-static comparator mix-up). No `69`/`15/15` literals.
4. **Safe checklist generator** — preflight (checksum verify, `npm whoami`,
   namespace 404 recheck) → explicit-SHA tag → publish → `dist.integrity` +
   dist-tag verification → GitHub release with artifacts.
5. **README corrections** — wrong `Bun.serve(app.serve(...).options)` example
   removed; CLI docs use public `bunx lugas …` form; status honestly states
   "publication-ready beta candidate … pending owner sign-off".
6. **Stale `release-evidence.json` (v1, bound to `34439dc`) removed** from the
   tree; the builder now requires fresh v2 evidence bound to the pinned source.

## Attestation status: ENVIRONMENT-LOCKED

Four attestation attempts were discarded as contaminated: this shared host
runs uncontrollable external load cycles (parallel rustc / .NET VBCSCompiler /
Chrome / uv builds; load spikes 12–29; sustained ≥ 9 for over two hours).
Measured throughput under those spikes was 13k–36k rps — the fail-closed gate
correctly refuses such evidence (exactly the M6R2–M6R5 behavior), but no valid
attestation can be produced on this machine under current conditions.

The required procedure (documented in the M6 gate addendum) must be executed
on a quiet host (load < 4); the builder then cross-validates every artifact
and publication follows the checklist. This is the fail-closed chain working
as designed — it cannot be satisfied by narrative.
