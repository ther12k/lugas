## Assumptions

- `bunCompatibility` reports the OBSERVED `Bun.version` at generation time (truthful observation, not a support-range claim) — the architecture doc's field name retained with tightened semantics.
- Modules sort by name (not declaration order) so manifests are stable across refactors that preserve semantics; guards keep execution order because order is semantic.
- Serialization is JSON with 2-space indent and trailing newline; key order follows the schema.
- Additive optional fields may land inside v1 only with a documented runtime source and lenient readers; anything else bumps the literal to `-v2`.
- ADR correction requirement is encoded directly in the spec's stability policy (implementation divergence opens an ADR, never silent edits).
