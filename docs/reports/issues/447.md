New `tests/release/package-consumers/installed-consumers.test.ts` (3 tests, gates included via unfiltered `bun test`):

1. **Clean-room typecheck** — the consumer installs its OWN toolchain from the registry (`typescript@7.0.2`, `@types/bun@1.4.0`, `zod@^4.4.3` — resolved 4.6.7 at evidence time) and compiles positive fixtures (params/query/headers/body slots, coerced query, and the typed client's ok/error result-union narrowing) with the documented [getting-started](https://github.com/ther12k/lugas/blob/main/docs/getting-started.md) tsconfig. A negative fixture proves three contract violations fail compilation: unknown path, wrong body type (`TS2322`), undeclared method (`TS2345`). *(Corrected 2026-11-27: the original said "discriminated union" — the fixtures' schemas are plain `z.object`; what they exercise on the union side is the client's per-status result narrowing, not schema-level union types.)*
2. **Browser-safety scan** — the `Bun.build` browser bundle AND the shipped `build/lugas-client.esm.js` must contain no quoted `bun:`/`node:` server-runtime specifier, and the bundle runs under Node with only a fetch stub. *(Corrected 2026-11-27: the original also claimed the scan proves no `drizzle-orm`/`zod` dependency imports — unverifiable, since both artifacts are bundled without `external`, so dependency inlining is guaranteed by the bundler and a bare specifier could never appear as text. 3. **Containment + identity** — all five export map entries resolve inside the consumer's `node_modules/lugas` in both modes (default → `src/*.ts`, `lugas-dist` → `dist/*.js`; `./client/browser` → the prebuilt artifact in both; Node `require.resolve` → dist fallback), never the checkout; and `app.manifest.frameworkVersion` equals the **installed** `package.json` version (itself equal to `CANDIDATE_VERSION`) in both modes.

## Erratum (2026-11-27)

Post-merge review found two overclaims and one assertion that cannot fail; the Outcome text above is corrected in place.

1. **"Same staging path as the rehearsal" (test header) was false.** The suite copies the working tree and applies only version/publishConfig/bin; the rehearsal stages `git archive HEAD` after refusing a dirty tree and additionally injects engines, repository, bugs, homepage, and keywords. This suite's evidence is about the working tree — including any uncommitted content at the time — not the committed candidate. The header and Outcome now say so.
2. **"Discriminated union" overclaimed the fixtures.** The positive fixtures use plain `z.object` schemas; the union exercised is the typed client's per-status result narrowing. Reworded.
3. **The dependency half of the browser scan could never fail.** A quoted `drizzle-orm`/`zod` specifier cannot survive a bundler run without `external` — inlining turns those imports into code. The scan now asserts only the `bun:`/`node:` half (which CAN fail), and the comment states exactly what the scan does and does not prove; dependency freedom rests on the bundler configuration and the Node execution.
4. **The `!startsWith(ROOT)` containment assertion in test 3 is tautological as written** — the consumer directory is constructed under `mkdtemp(tmpdir())` earlier in the same test, so it can never start with ROOT. The real containment evidence is the per-subpath `startsWith(installedRoot)` checks. Left in place as documentation, flagged here so it is not mistaken for an active guard.
5. Also recorded under Assumptions: the `zod` range floats ahead of README's verified version (see above), and the post-publication registry check is now tracked on #442.
6. **Exact-tarball candidate qualification lane added (LR2-04)**: Alongside the working-tree staging lane, `installed-consumers.test.ts` now includes an exact-artifact test that verifies pre-built candidate tarballs (`docs/releases/beta/lugas-0.1.0-beta.6.tgz` or `LUGAS_RELEASE_TARBALL`) and validates SHA-256 integrity without rebuilding, confirming checksum mismatch fails closed, files/exports/CLI exist, and resolution/runtime identity hold from the exact packaged bytes.
