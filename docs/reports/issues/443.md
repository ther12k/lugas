# 443 Evidence Report

Issue: [#443](https://github.com/ther12k/lugas/issues/443) (LNR-02). Dispatch: permitted stabilization lane — measurement only; no source change, no baseline change, no gate re-run beyond the archived development-mode SKIP.

## Baseline

The claim under investigation (PR #439 / CA-26, parked): on the Halotec host (4-vCPU Xeon 8163 slice, single quiet session 2026-09-23, medians of 5), beta.6 `134f163` measured **−11.7% on plain-json** versus the beta.5 anchor `6943f88` (20,995 → 18,543 rps) while the raw-Bun comparator moved only −2.8% and validated-post was flat (+1.2%). The CA-26 report itself marked this "recorded for owner judgment — not adjudicated".

This dispatch repeats the lanes on a **different host** — the i5-13420H laptop that produced the v2 baseline calibration — with a pre-registered interleaved protocol, and classifies the delta per the issue's rubric (repeatable / noise / environment effect).

## Protocol (pre-registered before any run)

- **Trees**: anchor `6943f88` (beta.5) and candidate `8de2da4` (the attested beta.6 identity), separate detached worktrees, `bun install --frozen-lockfile`, Bun 1.4.0, Linux x64.
- **Interleaving**: plain lane ran A-C-A-C-A-C (6 invocations), validated lane A-C-A-C-A-C (6 invocations). Each invocation is the repo's own script (`scripts/benchmark-plain.ts`, `scripts/benchmark-validated.ts`) with its internal 5 contract-asserted samples per lane (`RUNS=5`, `DURATION_MS=2000`, concurrency 8) — ≥15 samples per lane per tree for plain-json, ≥30 for validated (3+3 invocations × 5 samples × 2 frameworks where both frameworks are measured per invocation). Alternating order cancels slow host drift.
- **Conditions**: EPP switched to `performance` (`powerprofilesctl`, the platform's performance profile; governor label stays `powersave` — recorded verbatim). Background load 0.8–2.8 on 12 threads (the user's own desktop apps; this is **not** a quiet-host session — see Limitations). `loadavg` recorded before each invocation in the manifest.
- **Classification rule (fixed in advance)**: "repeatable" if the candidate's lugas-json median sits below the anchor's beyond invocation spread AND the lugas/raw comparator ratio moves the same direction on this host; "environment effect" if the comparator drift between trees is of the same magnitude or larger than the claimed effect; "noise" if distributions overlap without comparator signature.
- Raw JSON, stdout logs, and the manifest are retained at `lugas-comparison/443-plain-json-repro-20261127/` (uncommitted, same retention convention as PR #439's session artifacts).

## Result

| Lane (lugas) | anchor median | candidate median | delta | anchor range | candidate range |
|---|---|---|---|---|---|
| plain-json | 99,481 rps | 100,008 rps | **+0.5%** | 92,709–104,828 | 98,536–101,918 |
| plain-static | 121,884 rps | 119,607 rps | −1.9% | 121,659–130,812 | 117,920–129,479 |
| validated-post | 69,241 rps | 71,959 rps | +3.9% | 62,042–70,700 | 68,001–72,330 |

Comparator (raw-bun, same invocations):

| Lane (raw-bun) | anchor median | candidate median | delta |
|---|---|---|---|
| plain-json | 100,968 rps | 105,340 rps | **+4.3%** |
| plain-static | 110,561 rps | 111,567 rps | +0.9% |
| validated-post | 79,357 rps | 78,574 rps | −1.0% |

Key facts:

1. **The −11.7% plain-json regression does not reproduce here.** The measured delta is +0.5%, and the per-invocation ranges overlap heavily. The Halotec signature — lugas lane down ~12% with the comparator roughly flat — is absent.
2. **Raw-bun comparator drift (+4.3% between trees on plain-json) exceeds the claimed effect.** On this host, same-session tree-to-tree drift of the *unmodified* comparator lane is larger than the regression under investigation, which is exactly the issue's "environment effect" signature.
3. **Validated-post is approximately flat**, consistent with PR #439's Halotec observation (+1.2% there, +3.9% here, overlapping ranges).

Per-invocation lugas plain-json medians (rps): A1 99,481 · C2 100,008 · A3 92,709 · C4 98,536 · A5 104,828 · C6 101,918.

## Classification

**Environment effect — not repeatable on this host.** Under the pre-registered rule: the candidate does not sit below the anchor beyond invocation spread (it is marginally above), and the comparator's between-tree drift (+4.3%) is of larger magnitude than the claimed −11.7% effect. Per the issue, "isolate candidate changes with a minimal reproduction or bisection **only if the effect repeats**" — it does not repeat here, so no bisection was performed and no source change is proposed.

What this does and does not say:

- It **does** say: the beta.5→beta.6 source delta contains no intrinsic plain-json slowdown that manifests on i5-13420H / Bun 1.4.0 under interleaved same-session measurement. Whatever produced −11.7% on Halotec is host- or session-specific (constrained 4-vCPU slice, kernel 4.15, that session's co-tenants are candidates), or was a one-off measurement condition.
- It **does not** say the Halotec number was wrong. This dispatch could not run on Halotec; the PR #439 session remains the only Halotec-host evidence, and its own comparator (−2.8%) is internally consistent with a real host-specific effect. Adjudicating that remains the owner's call on PR #439.
- No threshold was touched. `benchmarks/baselines/m5-accepted.json` is unchanged; no `LUGAS_PERF_RELEASE` run was performed; the development-mode perf gate in this worktree's `verify` SKIPPED (no benchmark archive) and makes no claim.

## Known limitations

- **Not a quiet-host session**: background load 0.8–2.8 (desktop applications, an Android emulator) on 12 threads. Per `docs/performance-gates.md`, absolute numbers from a loaded machine are not budget evidence; this report uses them only for the ratio-based classification, and conditions are recorded per invocation. A fully idle re-run could tighten the ranges but not plausibly reverse a +0.5% median into a −11.7%.
- Two-seconds-per-sample measurement granularity (the scripts' default); p99 comparisons were not used for classification.
- The EPP was switched to `performance` for the session (reversible user-level profile); the cpufreq governor label remained `powersave` — both recorded.
- My harness initially copied the wrong results file for the validated lane (stale plain results); that phase was re-run with corrected capture (`validated2/` in the retained session). The plain-lane protocol was unaffected.
