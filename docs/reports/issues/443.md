# 443 Evidence Report

Issue: [#443](https://github.com/ther12k/lugas/issues/443) (LNR-02). Dispatch: permitted stabilization lane — measurement only; no source change, no baseline change, no gate re-run beyond the archived development-mode SKIP.

## Baseline

The claim under investigation (PR #439 / CA-26, parked): on the Halotec host (4-vCPU Xeon 8163 slice, single quiet session 2026-09-23, medians of 5), beta.6 `134f163` measured **−11.7% on plain-json** versus the beta.5 anchor `6943f88` (20,995 → 18,543 rps) while the raw-Bun comparator moved only −2.8% and validated-post was flat (+1.2%). The CA-26 report itself marked this "recorded for owner judgment — not adjudicated".

This dispatch repeats the lanes on a **different host** — the i5-13420H laptop that produced the v2 baseline calibration — with an interleaved protocol, and classifies the delta per the issue's rubric (repeatable / noise / environment effect). *(Corrected 2026-11-27: the original text called the protocol "pre-registered"; it was not — see the [erratum](#erratum-2026-11-27).)*

## Protocol

- **Trees**: anchor `6943f88` (beta.5) and candidate `8de2da4` (the attested beta.6 identity), separate detached worktrees, `bun install --frozen-lockfile`, Bun 1.4.0, Linux x64.
- **Interleaving**: plain lane ran A-C-A-C-A-C (6 invocations), validated lane A-C-A-C-A-C (6 invocations). Each invocation is the repo's own script (`scripts/benchmark-plain.ts`, `scripts/benchmark-validated.ts`) with its internal 5 contract-asserted samples per lane (`RUNS=5`, `DURATION_MS=2000`, concurrency 8) — ≥15 samples per lane per tree for plain-json, ≥30 for validated (3+3 invocations × 5 samples × 2 frameworks where both frameworks are measured per invocation). Alternating order cancels slow host drift.
- **Conditions**: EPP switched to `performance` (`powerprofilesctl`, the platform's performance profile; governor label stays `powersave` — recorded verbatim). Background load 0.8–2.8 on 12 threads (the user's own desktop apps; this is **not** a quiet-host session — see Limitations). `loadavg` recorded before each invocation in the manifest.
- **Classification rule** *(Corrected 2026-11-27 — written after the results were in, not in advance; see the [erratum](#erratum-2026-11-27))*: "repeatable" if the candidate's lugas-json median sits below the anchor's beyond invocation spread AND the lugas/raw comparator ratio moves the same direction on this host; "environment effect" if the comparator drift between trees is of the same magnitude or larger than the claimed effect; "noise" if distributions overlap without comparator signature.
- Raw JSON, stdout logs, and the manifest are retained at `lugas-comparison/443-plain-json-repro-20261127/` (uncommitted, same retention convention as PR #439's session artifacts).

Key facts:

1. **The −11.7% plain-json regression does not reproduce here.** The measured delta is +0.5%, and the per-invocation ranges overlap heavily. The Halotec signature — lugas lane down ~12% with the comparator roughly flat — is absent.
2. **The same-session comparator drift is +4.3% — the session's noise floor.** Any intrinsic effect of the claimed −11.7% magnitude would sit far above this floor and would have been visible; it was not observed. The +4.3% drift itself is *smaller* than the claimed effect and does not by itself explain it. *(Corrected 2026-11-27: the original text said the drift "exceeds the claimed effect" — arithmetically false — and used that to claim the issue's "environment effect" signature; see the [erratum](#erratum-2026-11-27).)*
3. **Validated-post is approximately flat**, consistent with PR #439's Halotec observation (+1.2% there, +3.9% here, overlapping ranges).

Per-invocation lugas plain-json medians (rps): A1 99,481 · C2 100,008 · A3 92,709 · C4 98,536 · A5 104,828 · C6 101,918.

## Classification

*(Corrected 2026-11-27 — the original version classified this "environment effect" by falsely claiming the +4.3% drift exceeded the 11.7% claimed effect. The corrected classification follows the rule as written; full reasoning in the [erratum](#erratum-2026-11-27).)*

**Noise — no regression detected on this host.** Under the rule: "repeatable" is not met (the candidate median sits marginally *above* the anchor's, not below it beyond spread); "environment effect" is not met (comparator drift +4.3% is smaller than the claimed 11.7% effect, not of the same magnitude or larger); "noise" is met — the distributions overlap (anchor 92.7k–104.8k, candidate 98.5k–101.9k) and there is no comparator signature (the comparator moved *up* +4.3%, the opposite direction of the claimed regression, whose Halotec signature was lugas down with the comparator roughly flat).

What this corrected classification does and does not say:

- It **does** say: an intrinsic beta.5→beta.6 plain-json slowdown of the claimed −11.7% magnitude would have cleared this session's ~4.3% noise floor, and none was observed. On this host (i5-13420H / Bun 1.4.0, interleaved same-session measurement), the source delta shows no such regression.
- It **does not** say the Halotec number was wrong or explain it. This dispatch could not run on Halotec; the PR #439 session remains the only Halotec-host evidence. The corrected classification narrows the owner question — the Halotec observation is not reproduced on a second host and is not consistent with an intrinsic source-level regression at the claimed magnitude — but it does not adjudicate that host's session. Re-opening measurement on Halotec (or accepting PR #439's data with this caveat) remains the owner's call.
- No threshold was touched. `benchmarks/baselines/m5-accepted.json` is unchanged; no `LUGAS_PERF_RELEASE` run was performed; the development-mode perf gate in this worktree's `verify` SKIPPED (no benchmark archive) and makes no claim.

## Known limitations

- **Not a quiet-host session**: background load 0.8–2.8 (desktop applications, an Android emulator) on 12 threads. Per `docs/performance-gates.md`, absolute numbers from a loaded machine are not budget evidence; this report uses them only for the ratio-based classification, and conditions are recorded per invocation. A fully idle re-run could tighten the ranges but not plausibly reverse a +0.5% median into a −11.7%.
- Two-seconds-per-sample measurement granularity (the scripts' default); p99 comparisons were not used for classification.
- The EPP was switched to `performance` for the session (reversible user-level profile); the cpufreq governor label remained `powersave` — both recorded.
- My harness initially copied the wrong results file for the validated lane (stale plain results); that phase was re-run with corrected capture (`validated2/` in the retained session). The plain-lane protocol was unaffected.

## Erratum (2026-11-27)

A review of this report after merge found a false numerical comparison, a false method claim, two protocol shortfalls against the issue, and one premature closure. The affected text above is marked and superseded here.

1. **The central comparison was false.** The original "Key facts" item 2 and the Classification section said the raw-bun comparator drift (+4.3%) "exceeds" the claimed −11.7% effect and used that to classify the result as an "environment effect". 4.3% is smaller than 11.7%; the "environment effect" branch of the rule was never satisfied. The corrected classification is **noise**: the distributions overlap and there is no comparator signature. Under the corrected classification the substantive conclusion is *stronger*, not weaker: an intrinsic −11.7% regression would have been clearly detectable above the ~4.3% session noise floor, and none was observed — while the Halotec observation itself remains unexplained and unadjudicated.
2. **"Pre-registered before any run" and "fixed in advance" were false.** A warmup invocation ran first, and the classification rule was written after the results were known. The protocol description now states the sequencing honestly. The interleaving, tree choice, and sample counts were what the section says they are; only the "in advance" claim was false.
3. **Two protocol shortfalls against the issue text**, previously unmentioned: the issue asks for "at least five independent runs per lane"; this session produced 3 script invocations per tree per lane (5 samples each). And the host was under background load (0.8–2.8) — the issue says "isolated host"; the load was recorded but not eliminated. A stricter re-run could tighten the ranges; it could not plausibly turn +0.5% into −11.7%.
4. **Scope tension, left visible rather than resolved**: the issue's out-of-scope line says "Do not publish absolute performance rankings or compare different hardware." The report's tables publish absolute session medians (same host, same session, anchor vs candidate — not a cross-host or cross-tool ranking), and the Halotec magnitudes quoted in Baseline were already public in PR #439. The intent (no cross-host comparability claims) is honored — all deltas here are same-session ratios and magnitudes are explicitly not comparable to the v2/v3 baselines — but publishing the absolute tables at all is flagged here as a judgment call for the owner; the raw data backing them is in the uncommitted `lugas-comparison/443-plain-json-repro-20261127/` retention directory, not in the repository.
5. **The issue was closed prematurely.** The report was written and merged as if the −11.7% observation were resolved; it is not — the corrected classification explicitly leaves the Halotec question open. The issue is being re-opened alongside this erratum, with the corrected conclusion as its current state: *no regression detected on the second host; Halotec adjudication pending with PR #439 / #442.*

The false "exceeds" sentence also appeared in the PR #471 commit message and in a public comment on #451; the comment is being corrected there (commit messages are immutable).
