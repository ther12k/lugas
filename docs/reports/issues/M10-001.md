## Outcome

### F1 — `rateLimit()`'s 429 is now a typed client outcome

Root cause (probe evidence in the issue): the guard's declared result union carried the **abstract** `Response` member. `TypedResponse<S, B>` is `Response & { [brand]?: { status, body } }` — the brand is optional, so the abstract member matched `TypedResponse<infer S, infer B>` with `S = number, B = unknown`, widening every rate-limited client call's outcome to `{ status: number; body: unknown }`. The construction-side change alone (this battery first tried `problem()`/`text()` with the old declaration) does **not** fix it; the declaration must carry the typed members.

Fix:

- `src/core/rate-limit.ts` — both 429 variants built through `problem(429, …)` / `text(429, …)` (typed helpers own the media types); declared result is now `GuardDescriptor<TServices, Promise<{ rateLimit: RateLimitInfo } | RateLimitBlockedResponse>>` with `RateLimitBlockedResponse = TypedResponse<429, ProblemFields> | TypedResponse<429, string>`.
- Wire bytes unchanged: same status, same headers (`Retry-After`, `RateLimit-*`), same bodies — all 11 M9-008 behavior tests pass **unmodified**.
- Client outcome union now discriminates precisely: `{ status: 429; body: string } | { status: 429; body: ProblemFields }` — pinned compile-time in `tests/types/rate-limit.test-d.ts` (`_t5`).
- `RateLimitBlockedResponse` exported from the root entry (additive type; protected-file edit owned by this issue).

### F2 — Agent docs fresh, and staleness now fails the gate

- `scripts/generate-llms.ts` rewritten: the doc-page inventory is **derived from `docs/*.md` on disk** at generation time with per-page summaries — new pages can no longer be silently missing (the generator self-flags as stale via `--check` whenever docs/ changes). Content updated with the shipped feature surface (cookies, WebSockets, hardening, uploads, telemetry, compression/ETag, rate limiting), agent surfaces, and the full diagnostic-code families. llms.txt: 2,910 → 4,895 bytes, still under the M4-014 5KB bounded-context bound (**bound not weakened**; content compacted instead).
- `scripts/generate-agent-docs.ts`: purpose line, a one-line-per-feature surface index (12 features with doc pointers), the full per-feature diagnostic table (13 new rows), and the skill's key-files list — `llms-full.txt` previously had **zero** mentions of any M9 surface.
- Both `--check` modes wired into `scripts/verify.ts` as `agent-docs-llms` and `agent-docs-full` steps — the gate that existed but was enforced nowhere (the root cause of the stale beta.4 release). A stale agent surface now fails `bun run verify`.

### F3 — Doc stitches

- `docs/client-error-semantics.md`: new "Guard-originated 429" subsection — typed outcome, body variants, the four rate-limit headers via `result.response.headers`.
- `docs/rate-limit.md`: new "Typed client and OpenAPI" section — precise client discrimination, `route({ openapi })` cross-reference.

## Security considerations

## Known limitations

- The agent-doc generators remain content-hardcoded except the llms page inventory (which is disk-derived); full content scraping is out of scope for a fix battery.
