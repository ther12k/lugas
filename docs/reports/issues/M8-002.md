# M8-002 Evidence Report

Issue: [#349](https://github.com/ther12k/lugas/issues/349) · ADR: [ADR-0023](../../okf/decisions/0023-server-sent-events-helper.md) (amended in-scope, below) · Dispatch: [ODR-0008](../../owner-decisions/m8-002-dispatch.md)

## Baseline

Branch base: `3b1f29d` (merge of PR #350 — ADR-0023 + ODR-0008 on green main
`e67b2d4`, which already carried M8-001). Pre-existing state: no SSE support
anywhere; no `sse` symbol; the diagnostics catalog ended at the CORS family.
Design-load probes (Bun 1.4.0, Linux x86-64, recorded in ADR-0023):
`request.signal` aborts on client disconnect and cancels the response stream;
`server.stop(true)` with an open stream takes the same path.

## Outcome

`sse({ start, heartbeatMs? })` — a streaming `text/event-stream;
charset=utf-8` response (`Cache-Control: no-cache`) in the root subpath:

- **Producer lifecycle:** `start(writer)` runs synchronously inside `sse()`,
  before any wire bytes; its optional returned cleanup runs **exactly once**
  on every end path — `writer.close()`, client abort (signal → stream
  cancel), server force-close (`stop(true)` and drain-deadline expiry). A
  `close()` called *inside* `start()` runs the returned cleanup immediately.
  The heartbeat timer is helper-owned and cleared on the same path.
- **Writer:** `send({ data, event?, id?, retry? })`, `comment`, `retry`,
  `close`, `desiredSize`. Post-end sends return `false`, never throw. Data
  shares `json()`'s `JSON.stringify` wire semantics (non-finite → `null`,
  pinned M6R9 behavior); multi-line/CRLF data splits into `data:` lines.
- **Pure serializer exported:** `formatSseEvent` — field order `id`, `event`,
  `retry`, `data`, blank-line terminator (matches ADR-0023; an implementation
  draft emitted `retry` before `event` and was reordered to the ADR before
  commit).
- **Diagnostics:** `LUGAS_SSE_001` (config shape/keys/heartbeatMs),
  `LUGAS_SSE_002` (event input, forbidden field newlines, non-serializable
  data) — registered in the frozen catalog; goldens regenerated.
- **Exports:** `sse`, `formatSseEvent` (values) + `SseConfig`, `SseWriter`,
  `SseEventInput` (types) from `src/index.ts` — the ODR-0008 protected-file
  authority; `package.json`/`bun.lock` untouched.

**ADR-0023 amendment (in-scope, recorded in the ADR Status):** implementation
probing showed a mid-stream error on a zero-byte response surfaces to clients
as a **silent `200` with an empty body** — the ADR draft's "start throws →
stream errors → client sees a connection failure" is not what the runtime
does. Decision point 4 was strengthened instead of shipped as drafted:
`start()` executes before the `Response` exists, so a throw propagates
through the route's error policy as a redacted `500` Problem Details (pinned
by test: status 500, `application/problem+json`, title only, no producer
detail). Decision point 5 gained the header-flush fact: Bun flushes response
headers with the first written byte, so an idle producer delays response
delivery — producers open with an initial event/`retry`/comment.

## Assumptions

- EventSource (browser) is the consumer; `lugas/client` intentionally gains
  no SSE surface (request/response client; ODR-0008 boundary).
- `retry` inside `send()` is accepted for completeness though `writer.retry`
  is the idiomatic standalone hint; the spec treats `retry:` as a control
  field either way.
- Idle-stream header flush is HTTP/runtime-inherent (probe), documented as
  producer guidance rather than papered over with a hidden priming byte.

## Security considerations

- No `Access-Control-*` semantics changed; SSE streams pass through the
  ADR-0022 policy wrappers (pinned), so a configured policy cannot be bypassed
  by switching a route to streaming.
- Error redaction holds: a throwing producer becomes the standard redacted
  `500` problem — producer error messages never reach the wire.
- Writer input diagnostics reject newline-bearing field values, preventing
  frame-injection through `event`/`id`/comment fields; data splitting is the
  serializer's single point of framing.
- Heartbeat/producer timers are always cleared (close, cancel, force-close);
  the exactly-once contract prevents double-unsubscribe storms on reconnect.

## Known limitations / Not exercised

- `send()` is enqueue-only: producers ignoring `desiredSize` can buffer
  unboundedly against a stalled client (documented producer responsibility;
  ADR-0023 revisit trigger for drop policies).
- No real-browser `EventSource` lane (matches the recorded compatibility
  boundary: real browsers are not in the per-OS CI matrix); wire-level
  assertions are byte-exact against the WHATWG frame grammar.
- Reconnect bookkeeping (`last-event-id` resumption) is application-owned by
  design; the helper exposes no session state.
- Windows CI timing for heartbeat tests is generous (15 ms timer, 3 s
  read deadlines) but still wall-clock dependent.
