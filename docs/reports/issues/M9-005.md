# M9-005 Evidence Report

Issue: [#372](https://github.com/ther12k/lugas/issues/372) · ADR: [ADR-0030](../../okf/decisions/0030-multipart-forms.md) · Dispatch: [ODR-0014](../../owner-decisions/m9-005-dispatch.md)

## Baseline

Branch base: `ab12bee` (merge of PR #373 — M9-005 governance on green main `4f5a298`, carrying the M9-004 hardening battery).
Pre-existing state: no multipart surface; `formData()` available only as raw Bun (unbounded); diagnostic catalog ended at `LUGAS_HEALTH_002`.

## Outcome

`body: form(config?)` — a first-party multipart body codec for the existing body slot (ADR-0030):

- **Bounded consumption:** `Content-Length` above the effective budget refused pre-read; the body is read stream-wise and the read aborted at the cap — both `413 BODY_BUDGET_EXCEEDED` before any parse. Only capped bytes ever reach a parser.
- **Platform parse:** the buffered bytes are re-wrapped in a synthetic request and parsed by Bun's `FormData` implementation. No Lugas MIME parser exists (boundary/quoting/encoding corner cases stay with the maintained platform code).
- **Handler contract:** `ctx.body = { fields: Record<string, string>, files: Record<string, File> }` — native `File` values, repeated part names last-wins (documented, mirroring `parseCookies`; native `request.formData()` remains the multiplicity escape hatch). Compile-time: `DeclaredSlot` recognizes the descriptor so `ctx.body` is `MultipartBody`, not `undefined` (caught by verify's typecheck through the example — fixed, noted below).
- **Limits:** `maxFields` (64), `maxFiles` (16), `maxFileSize` (10 MiB) — each enforced with `413 FORM_LIMIT_EXCEEDED` (verified live for the file-size limit).
- **Honest failures:** non-multipart/missing-boundary → `415 UNSUPPORTED_MEDIA_TYPE`; unparseable multipart → `400 MALFORMED_MULTIPART`; both verified over a real server.
- **Budget composition:** route `budget` overrides app `bodyBudget` for multipart routes (verified: 4096 route budget admits a 1 KiB file under a 64-byte app default); manifest records the body capability (`validates: ["body"]`).
- **Diagnostics:** `LUGAS_FORM_001` (invalid limits/unknown keys) at creation; wire codes `MALFORMED_MULTIPART` and `FORM_LIMIT_EXCEEDED` join the Problem Details envelope family with their own `type` URIs (wire codes, not thrown-diagnostic catalog entries, per ADR-0030 §8).

## Assumptions

- Buffered-then-parsed (no incremental part events) is the honest cost of refusing-before-parsing; spooling behavior for large caps is platform-owned (ADR-0030 non-goals).
- Last-wins repeated names mirrors `parseCookies`; multiplicity has the documented native escape hatch.
- `Content-Length` is advisory (spoofable) — the stream cap is the real enforcement; the header check only avoids reading doomed bodies.
- An empty body (`request.body === null`) with a multipart content type is malformed (no boundary-terminated parts can exist).

## Security considerations

- The budget guarantee now covers the heaviest request class: over-budget uploads die before parsing, and only capped bytes reach any parser.
- The platform MIME parser owns the adversarial parsing surface (boundary smuggling, folding, quoting) — Lugas adds no parser of its own.
- Form limit failures and parse failures carry fixed Problem Details shapes; part values/field data never enter diagnostics or error bodies.
- `form()` rejects unknown keys and non-positive limits at declaration time — no silently inert limits.

## Known limitations / Not exercised

- No incremental part events; bodies buffer within the cap before parsing (ADR-0030 non-goal).
- Last-wins maps lose multiplicity (native escape hatch documented).
- Spooling behavior for very large `maxFileSize` caps is Bun's `File` implementation, not configured by Lugas.

## Deferred work

- `form.all()` multiplicity accessor or a streaming variant — ADR-0030 revisit trigger, by amendment with benchmarks.
- Typed field validation over `ctx.body.fields` via Standard Schema (post-parse) — composes today in handlers; a slot-level integration would need its own ADR.
