## Erratum (2026-11-26)

A re-verification found three defects in the documentation PR #465 shipped, and one false statement in this report.

1. **`docs/client.md` used a key that does not exist.** A `route()` snippet read `route({ headers: cookieHeader, guards: [session] })`. Guards are declared under `before` (`src/core/route.ts`; every example). It was the only `guards:` route key in the repository, and it had been synced to the website. Corrected.
2. **An example that would not type-check.** The `{ headers: {} }` idiom was annotated with a *required* header schema (`authorization: z.string()`), for which an empty headers object is invalid. The idiom is about optional declared headers; corrected to the optional case `examples/realworld/client.ts` actually uses.
3. **"Result shapes on bun-sqlite" stated two things that are not true of the pinned version.** It said `.run()` resolves `void` with "no inserted id, no affected row", and that `.get()` returns a values-array in general. Both were copied from `docs/reports/dogfood-realworld-findings.md` (RF-2) and `examples/realworld/README.md`. Probing drizzle-orm 0.45.2 on Bun 1.4.0 (Linux):

   | Read path, one matching row | Result |
   |---|---|
   | ``db.get(sql`SELECT …`)`` | `[1, "ada"]` — values-array |
   | ``db.all(sql`SELECT …`)`` | `[{ id, name }]` |
   | `db.select().from(users).where(…).get()` | `{ id, name }` — row object |
   | `await db.query.users.findFirst(…)` | `{ id, name }` — row object |

   `.run()` returns `{ changes, lastInsertRowid }`, declared as Bun's `Changes` in `drizzle-orm/bun-sqlite/session.d.ts:45`. `.all()` returns `[]`, never `undefined`, when no rows are produced. The guide and example README now reflect those results; the findings report preserves the original finding and corrects its disposition.
4. **This report's "every technical claim is grounded" line was false.** The drizzle and `ws.publish` statements had been checked for agreement with the example, which is where the error came from, not against the runtime.

`ws.publish` not echoing to the sender was then checked at runtime on Bun 1.4.0: two subscribed sockets, a publish from one socket's server-side handle, and that socket's client received nothing. It holds.

The cookie guidance was also narrowed. The explicit `cookie` header is a server-runtime pattern (pinned by `examples/realworld/client.ts` under Bun). In a browser, `Cookie` is a forbidden request header, so the browser attaches cookies itself and cross-origin sessions depend on the `credentials` mode the client forwards through platform options. That browser half follows from the Fetch standard and `src/client/request.ts`; it was **not** run in a browser.

Related, left alone: `examples/realworld/app.ts` checks `.all()` results against `undefined`, which cannot fire. Parked PR #437 corrects it (issue #444).
