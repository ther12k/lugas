At base, the dogfood findings report (`docs/reports/dogfood-realworld-findings.md`, 2026-09-11) recorded four frictions observed while building `examples/realworld/` strictly from the public docs, each still unresolved in the canonical docs:

- **RF-2** — drizzle `bun-sqlite` result shapes (`.get()` values-array, `.run()` void) documented only in the example README, never in `docs/drizzle.md`.
- **RF-4** — the `{ headers: {} }` idiom (declaring a headers schema makes the client options argument required) undocumented.
- **RF-5** — the typed-client cookie story ended at "use plain fetch"; no guidance for declaring the `cookie` header.
- **RF-7** — `ws.publish` does not echo to the sender; documented only in the example README.

RF-1, RF-3, RF-6 were already resolved (bindServices, CA-5/CA-6, in-PR docs fix respectively).

## Outcome

All four frictions now have first-class documentation; the findings report dispositions are updated to resolved.

- `docs/drizzle.md` — new **"Result shapes on bun-sqlite"** section (RF-2): the two surprising shapes, the `RETURNING` + `.all()` single-row pattern with code, the "driver behavior, adapter passes through untouched" boundary, and a pointer to `examples/realworld/`.
- `docs/client.md` — new **"Headers: the declared schema is the only channel"** section (RF-4): the options-required consequence with the `{ headers: {} }` idiom, and the no-undeclared-headers rule grounded in the actual mechanism (`OWNED_INIT_KEYS` reserves `method`/`body`/`headers`; platform `init` ownership throws `LUGAS_CLIENT_007` — verified in `src/client/request.ts:5,196-203`). New **"Sending cookies"** subsection (RF-5): declare the `cookie` header schema, forward the pair through it, no built-in cookie jar, plain-fetch `Set-Cookie` capture, browser-jar note, WebSocket query-token cross-reference — the strictness itself unchanged by design.
- `docs/websockets.md` — new **"`ws.publish` does not echo to the sender"** bullet under "What Lugas does not do" (RF-7), with the self-state-must-be-set-locally guidance and example pointer.
- `docs/reports/dogfood-realworld-findings.md` — RF-2/4/5/7 dispositions updated to **resolved** with pointers to the new sections; RF-5 explicitly marked "resolved as guidance" since the API-shaped strictness is unchanged.
- `website/src/content/docs/{drizzle,client,websockets}.md` — the same additions applied to the site copies, following the site conventions (frontmatter kept, relative links rewritten to `/lugas/<page>/`, example links as absolute GitHub URLs).

Every technical claim is grounded: drizzle shapes and cookie pattern verified against `examples/realworld/{app.ts,client.ts,README.md}`; the header-ownership rule against `src/client/request.ts`; the publish semantics against Bun's native pub/sub behavior as exercised in the realworld presence code.
