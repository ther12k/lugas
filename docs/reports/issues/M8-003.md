# M8-003 Evidence Report

Issue: [#352](https://github.com/ther12k/lugas/issues/352) · ADR: [ADR-0024](../../okf/decisions/0024-structured-logging.md) · Dispatch: [ODR-0009](../../owner-decisions/m8-003-dispatch.md)

## Baseline

Branch base: `1b72eec` (merge of PR #353 — ADR-0024/0025 + ODR-0009 on green main `0d52702`, carrying M8-001 and M8-002).
Pre-existing state: no logging facility in the framework; `defineApp()` did not accept `logging`. Diagnostic catalog ended at `LUGAS_SSE_002`.

## Outcome

`defineApp({ logging })` implements the ADR-0024 contract:

- **Sink Contract:** Emits structured, scalar-only entries (`LugasLogEntry`) to a pluggable `sink: (entry) => void` (default: JSON line to the matching `console` method). Zero vendor dependencies; cleanly adapts to Pino, OpenTelemetry loggers, or custom collectors.
- **Redaction by Construction:** Entry schema strictly allows only primitive scalar values (`string | number | boolean | null`). Headers, bodies, query params, cookies, and tokens are never logged by the framework.
- **Access Logging:** Opt-in `access: true` logs each completed request at `info` level with `method`, `path`, `route` (matched pattern or `"-"`), `status`, `durationMs`, and optional `requestId`.
- **Request IDs:** Opt-in `requestIds: true` generates UUIDs, sets the `x-request-id` response header, and correlates into access logs.
- **Compile-Boundary Enforcement:** The logging wrapper sits inside the CORS wrapper (so preflight `OPTIONS` requests are not logged as access events) and outside the traffic gate / error policy (so held 503s and 500 errors are logged with honest durations).
- **Diagnostics & Types:** Registered `LUGAS_LOG_001` in the catalog; updated `LUGAS_APP_002` hint to include `logging`; exported types from `src/index.ts` under ODR-0009 authority.

## Assumptions

- Access logs default to `false` (explicit opt-in, per ADR-0024 and roadmap integration defaults).
- CORS preflights are an infrastructure negotiation step handled at the outer boundary and are intentionally excluded from application access logs.

## Security considerations

- Complete data redaction by design: the closed schema guarantees no sensitive headers, query parameters, or body contents leak into log aggregation systems.
- UUIDv4 request IDs generated via standard `crypto.randomUUID()`.
