# M6R10 — toJSON semantics: one hook per serialization position (#321)

## Baseline

- `main@6037614` (post-M6R9 merge, PR #320; #319 closed; #315 open).
- Trigger: follow-up review finding that `Jsonify` modeled `toJSON` as a recursively chained transformation, while ECMA-262 invokes it at most once per serialization position. Release-blocking for the typed-wire claim; #315 deferred until fixed.
- Reproduction before implementation — runtime ground truth on `6037614` with hook call-counters: root stringify of the chained pair → `outer: 1, inner: 0`; keyed hooks receive `"value"`/`"0"`; hook→bigint → `TypeError`. Type probe: `Jsonify<Outer>` → `never` (truth `{ keep: "x" }`), `Jsonify<{ value: Outer }>` → `{}` (truth `{ value: { keep: "x" } }`), `Jsonify<[Outer]>` → `[null]` (truth `[{ keep: "x" }]`), `Jsonify<Keyed>` → `{}` (hook missed), `Jsonify<{ value: HookBig }>` → `{}` (throw mis-classified as drop).

## Findings and outcomes

1. **P1 — chained hook model.** Replaced with the two-phase model: `HookOnce<T>` unwraps `toJSON` at most once per position (key-bearing signature `(key: string) => infer J` accepted — zero-arg hooks remain assignable); `JsonifyAfterHook<T>` serializes the post-hook value without consulting `toJSON` again at that position; member (`JsonifyProperty`) and element (`JsonifyElement`) positions restart `HookOnce` — exactly the specification's per-position hook.
2. **Keyed hooks missed.** Fixed by the `(key: string)` pattern.
3. **Hook→bigint mis-classified as drop.** The throw outcome now has an internal sentinel (`JsonThrows`) distinct from `never` (= serializes to `undefined`). Drop classification reads the raw post-hook result: `never` → drop (key omitted / element `null`); sentinel → throw (member stays **required** with value `never`); anything else → value. The public `Jsonify<T>` strips the sentinel to `never`, so root/bigint-style brands are unchanged (`Jsonify<{ id: bigint }>` → `{ id: never }`).
4. **Bookkeeping (accepted):** M6R9's evidence described that wave as compile-time-only in a summary phrase ("zero runtime change" in the PR text lineage); the `LUGAS_RESPONSE_005` root-body check was an intentional runtime correction. This report supersedes that wording.

## Implementation notes

- `JsonifyRaw<T> = JsonifyAfterHook<HookOnce<T>>` is internal; `MemberDrops` reads `JsonifyRaw` (sentinel-preserving) so a hook-throw can never be counted as a drop — this was the root cause of the M6R9-era conflation.
- The `any` trap stays first; array/tuple mapping unchanged; `Simplify` flattening unchanged (brand stays identity-comparable).
- The previous recursive unwrap (`Jsonify<J> → Jsonify<J> → …`) is gone: there is no same-position recursion anywhere in the type.
- Existing M6R7–M6R9 assertions required **zero changes**: every previously locked case involves single-invocation hooks, which both models treat identically — the new assertions (`tests/types/response-tojson-position.test-d.ts`, 13 cases) lock the position semantics the old model got wrong.

## Assumptions

- The key-parameter pattern is `(key: string)`; hooks declaring fewer parameters (`() => J`) remain assignable to it, as do looser key types (`unknown`/optional). Hooks with unrelated first-parameter types still fall through to ordinary mapping — the same treatment `JSON.stringify` gives non-callable `toJSON`.
- Objects exposing a non-callable `toJSON: number` keep serializing that member like any other property (both in JS and in the model).

## Security considerations

- Compile-time only this wave; no runtime path changed. The throw sentinel is a type-level construct and never appears in any runtime artifact.

## Known limitations

- A union member whose serialization throws hides inside the surviving branch's type (e.g. `bigint | string` member types as `string`); if the throw branch is taken at runtime the response fails before existing — the brand describes the non-throwing outcome.
- Objects with `toJSON` plus additional enumerable members: the hook's result replaces the value entirely (per spec), so the model ignores the other members when a hook exists — matching `JSON.stringify`.
