## Assumptions

- Guard short-circuit statuses enter client unions via explicit `TResult` generics on `guard()` (union of Response | enrichment-marker); `ExtractGuardResponse` distributes over that union correctly. Pass-through returns a marker object merged into context.
- The 415 scenario is exercised by a nonconforming direct fetch probe (text/plain against a body-validating route); the canonical typed client always emits JSON content types by design. The escape hatch additionally probes raw 422 query validation.
- Abort observability is client-side (rejection + no fabricated result); handler-level cancellation visibility is platform-dependent and belongs to M5-013 stress work.
- Handler context reads use targeted annotations plus one `!` on a validated param (`ctx.params.id!`) because the static context type is `Record<string,string>` under `noUncheckedIndexedAccess`.
