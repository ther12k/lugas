## Assumptions

Recorded before coding:

1. **Classifier accepts functions.** `classifyRoute()` gains a `native-handler` kind for plain functions (sync, async, Promise-returning). Bun's native router accepts function values both at path level (`routes["/x"] = fn`) and inside method maps (`{ GET: fn }`) — pinned-oracle facts. Previously all functions were rejected (`unsupported`), contradicting the manifest's documented native `"handler"` shape and the frozen v1 taxonomy.
2. **M4R1-001's interim pass-through is superseded.** The ad-hoc `typeof entry === "function"` bypass in `prepareApp()` is removed; classification flows through the single classifier again (no second route representation).
3. **No more constructor-name guessing.** `compile-pipeline`'s fast path collapses to one code path: invoke, then `isPromiseLike(out)` ? resolve+assert : assert. A plain function returning `Promise.resolve(Response)` succeeds (review P1-2 bug fixed); fully sync chains stay synchronous with zero Promise allocation.
4. **`CompiledRoute.isAsync` redefined as declarative metadata**, not control flow: `body schema present || handler has [[AsyncFunction]] toString tag`. Rationale: the tag is intrinsic and survives minification/rebinding (unlike `constructor.name`, which breaks under bundlers). Existing merged assertions stay green (sync→false, async→true); a plain function returning a Promise reports `false` because it is *declared* sync — the runtime no longer depends on this flag, so the declaration cannot cause misbehavior. This is an intentional semantics clarification, recorded here before coding.
5. **Outdated merged expectation updated as owned correction**: `tests/unit/route-classification.test.ts` asserts `classifyRoute(() => new Response()).kind === "unsupported"`. That encoded the divergent classifier; it is updated to expect `native-handler` (the manifest/frozen-v1/native-Bun truth), not weakened.
6. **Unsupported values still fail closed** with unchanged codes/messages (`LUGAS_ROUTES_002/003`).
7. **No public API change**; `native-handler` is an internal union variant.

## Type/runtime/bundle impact

- Internal union variant added (`native-handler`); no public API change.
- Runtime: functions now serve natively at all positions; fast-path control flow simplified (one closure instead of two); advisory flag no longer drives behavior.

## Security considerations

- Function handlers receive the same error-policy wrapping? No — they are raw Bun passthroughs by contract (identical to raw Bun), so Lugas redaction does NOT apply to them. This is pinned-oracle conformance, documented in docs (M1-014 notes raw Bun dev-page exposure). Applications wanting redaction use descriptors. Recorded explicitly for gate review.

## Known limitations

- Raw Bun semantics apply to bare functions: no validation, guards, or error-policy wrapping. This is the documented conformance target ("behaves sama dengan raw Bun"), not an oversight.
