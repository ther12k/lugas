## Outcome

`defineApp()` accepts an opt-in `assets` configuration: `files` (literal exact
paths) and `dirs` (explicit prefixes ending in `/*`). Declarations are
validated and compiled to **native Bun route values** wrapped in GET-keyed
method maps — Bun serves assets natively (MIME, ETag/Last-Modified/304,
ranges, native asset 404); Lugas adds no filesystem server, MIME map, or cache
layer. Absent `assets`, every behavior is unchanged (regression-tested).

Contract implemented as accepted:

- **Ownership (fail-closed):** mutual pattern overlap between any asset
  declaration and any API route (root or module) or another asset declaration
  is rejected at startup (`LUGAS_ASSET_002`) — never resolved by spread order
  or Bun match specificity. Root catch-alls (`/*`) and param/wildcard file
  mappings are rejected (`LUGAS_ASSET_001`); declarations must point at
  existing content (`LUGAS_ASSET_003`).
- **Method contract:** asset mounts serve through GET and HEAD; other methods
  reach the app's not-found policy through the assembled routing
  configuration. No 405 promised. Asserted for **both mapping forms** with
  response **bodies** (no file bytes, not the app shell), not just statuses.
- **Misses:** missing file in a mount → native asset 404 (no HTML, no
  not-found fall-through); unknown API-namespace path → the API not-found
  response; anything else → the app's not-found policy.
- **Boundaries:** asset routes produce **no manifest facts** and bypass the
  request pipeline (guards and `onError` verified uninvolved); documented in
  `docs/getting-started.md` and `docs/api-reference.md`. New diagnostic codes
  `LUGAS_ASSET_001..004` are in the registry and catalog.

## Raw-request provenance: bounded normalization findings (owner merge condition)

Review required establishing WHERE encoded-path normalization happens before
treating the equivalence observation as server behavior. A committed
discriminator (`tests/static/raw-request.test.ts` + `tests/static/raw-http.ts`)
sends the request-target **verbatim over raw TCP** — no URL parser in the
path — and records the outgoing request line and response:

- **Bounded conclusion:** For the tested verbatim request targets on the
  recorded runtime, the native asset path returns an empty 404 without
  invoking application not-found handling. The corresponding high-level-client
  request is normalized before transmission (WHATWG URL Standard).
- **Raw `GET /assets/%2e%2e/index.html` → bare `404`, empty body.** The
  directory mount contains the path at the filesystem boundary; Bun's server
  performs **no** route-table re-dispatch of encoded dot-segments, and the
  request never reaches the app's `notFound` policy (native decline).
- **`fetch` with the same spelling → `200`, byte-identical to `/index.html`.**
  The equivalence is produced **client-side**: the URL Standard parses string
  inputs, treats `%2e%2e` as a double-dot path segment, and removes the
  preceding segment before the request is transmitted over the wire.

The earlier report's hypothesis was corrected by this evidence: at the server,
verbatim encoded traversal targets are contained (404) at the transport/native
boundary; high-level clients normalize paths prior to network dispatch.

**Authorization preservation (owner merge condition)** — pinned in
`assets.test.ts` ("encoded path normalizing onto a guarded API route..."): a
guarded `/api/private` responds identically to the direct and the
client-normalized encoded spelling (guard runs, protected handler gated on 401,
authenticated request reaches the handler), while the **raw** encoded target
is declined pre-route with a bare 404 (guard and handler uninvolved, no protected bytes).

**Scope clarification of the boundary finding:** "guards and `onError` are
uninvolved" applies to requests actually handled by the native asset mount
only. A request whose original spelling begins with an asset prefix but
normalizes onto an API route is an ordinary API request and receives the full
pipeline (guard included) — asserted, not assumed.

## Security considerations

- Public-directory boundary documented (protected files outside mounts; case-sensitivity caveat).
- Symlink containment: capability check verifies outside-root sentinel exists, symlink resolves to it through ordinary filesystem access (`readFileSync`), and HTTP request through asset mount returns 404 without exposing sentinel token. In CI compatibility lanes, an unavailable fixture fails the run to prevent silent satisfaction.
- Case sensitivity: probed independently via ordinary filesystem access (`existsSync(variedFile)`). On case-insensitive volumes, public asset resolves (200); on case-sensitive volumes, variation is a miss (404). Documented that case variation resolution reflects underlying filesystem semantics, not an authorization boundary.
- The raw-request provenance and bounded normalization conclusions are pinned by deterministic regression suites.
