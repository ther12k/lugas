# CA-20 Evidence Report

## Baseline

- Base commit: `075599a` (Merge pull request #430 — beta.5 shipped at 6943f88)
- Branch: `agent/CA-20-dual-distribution` / Worktree: `.worktrees/CA-20`
- Bun version: 1.4.0 (x64 Linux)
- Owner design adopted 2026-09-14: one package, two execution modes — raw
  TypeScript as the Bun default through the `bun` export condition, emitted
  JavaScript via an explicit `lugas-dist` condition, dist as the fallback for
  tools that do not select Bun's condition. Same `.d.ts` contract for both
  modes. New unpublished version (0.1.0-beta.6); beta.5 and its attestations
  unchanged.

## Mechanism verification (before wiring)

Sandbox package with the exact condition order (`types`, `lugas-dist`, `bun`,
`import`, `default`), verified on Bun 1.4.0:

| Check | Result |
|---|---|
| Runtime default import → src tree | ✓ (`src/index.ts`) |
| Runtime `--conditions=lugas-dist` → dist tree | ✓ |
| `Bun.resolveSync` default → src path | ✓ |
| `Bun.resolveSync` lugas-dist → dist path | ✓ |
| Bundler `--target=bun` default → src; with `--conditions=lugas-dist` → dist | ✓ |
| Bundler `--target=node` → dist fallback | ✓ |

## Outcome

1. **Export map** (`package.json`, owning issue): `.`, `./client`, `./drizzle`,
   `./testing` each carry `types → dist/*.d.ts`, `lugas-dist → dist/*.js`,
   `bun → src/*.ts`, `import`/`default → dist/*.js` — condition order
   `types, lugas-dist, bun, import, default`. `./client/browser` unchanged
   (prebuilt standalone artifact). `files` now ships `src` alongside `dist`
   and `build`. `bin` unchanged (`dist/cli/main.js`).
2. **Candidate version** bumped to `0.1.0-beta.6`
   (`scripts/release/candidate-version.ts`, single source).
3. **Staging order preserved and proven**: the existing pipeline already
   stamps the staged source (`src/internal/framework-version.ts`) BEFORE
   generating dist from it; the rehearsal now asserts the shipped src tree
   carries the candidate stamp (raw-default identity), closing the owner's
   "stamp source first" requirement mechanically.
4. **Rehearsal additions** (`scripts/release/package-beta.ts`):
   default resolution → `src/index.ts`; `--conditions=lugas-dist` →
   `dist/index.js`; subpath `./client` honors the policy; Node
   `require.resolve` → dist fallback; compiled-mode server consumer runs with
   `fw=<candidate>`; tarball ships both representations.
5. **Test suite** (`tests/package/dual-distribution/dual-distribution.test.ts`,
   5 tests): staged pack contents + one stamped version across src and dist;
   default raw-TS resolution + runtime identity; lugas-dist resolution +
   runtime identity; subpath policy + Node fallback; `./client/browser`
   artifact. Fixes a version-coupled fixture in
   `tests/unit/verify-perf-gate.test.ts` (tarball name now derived from
   `CANDIDATE_VERSION`).

No runtime code changed. The `src/` tree is the existing committed source;
`dist/` is generated by the existing builder. TypeScript resolution is
unaffected (editors/tsc select `types` → `dist/*.d.ts`; TS does not match the
`bun`/`lugas-dist` conditions without explicit `customConditions`).

## Security considerations

- No runtime code changed; the shipped `src/` tree is the same audited source
  the repository builds `dist/` from.
- `files` whitelist still excludes tests, benchmarks, worktrees, release
  tooling; the forbidden-prefix rehearsal check passes with `src/` added.

## Known limitations

- Direct `lugas/dist` imports are not exported (no such subpath) — mixed
  src/dist resolution is structurally prevented rather than discouraged only.
- Startup cost of the raw-TS default depends on Bun's transpile cache state
  (owner-acknowledged tradeoff; the compiled mode is the opt-out).
