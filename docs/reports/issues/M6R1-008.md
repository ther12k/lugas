# M6R1-008 Evidence — Second-line fallback for custom error policies

## Baseline
- Base commit: `292f1e8` (main, M6R1-009 merged)
- Issue: #263 (M6R1-008)
- Bun/TypeScript: 1.4.0 / 7.0.2, Linux x64

## Outcome

Completed. `withErrorPolicy` now guards its own invocation of app-provided
policies. A custom `onError` that throws, rejects, returns a non-Response
(sync or async) triggers a second-line redacted fallback: the default 500
problem (`application/problem+json`, title only), never Bun's development
error page, never the original error text, never a policy stack trace.
A one-line server log notes the policy failure (method + path only).
Healthy custom policies retain full control of the response (503 passthrough
covered by test).

Not-found policies were already shape-checked implicitly (Bun requires a
Response for notFound); the redaction-critical path is onError and is fully
covered here.

## Security considerations
Closes a redaction-bypass path: previously a faulty custom policy converted a
caught internal error into an unhandled rejection rendered by Bun's dev error
page (message + stack). Fallback responses contain no error details.

## Known limitations / deferred
Custom notFound policies are validated for function-ness at startup but their
runtime failures follow the same fallback need; covered by the shared
`redactedFallbackResponse` only when routed through handleError — deferred if
deemed necessary in review.
