# M6R1-007 Evidence — CLI timeout contract: exitedDueToTimeout + --timeout validation

## Baseline
- Base commit: `f52a0a8` (main, M6R1-008 merged)
- Issue: #262 (M6R1-007)
- Bun/TypeScript: 1.4.0 / 7.0.2, Linux x64

## Outcome

Completed. Two CLI contract defects fixed:

1. Timeout detection now keys on Bun's `exitedDueToTimeout` property
   (the documented source of truth for spawnSync timeouts) instead of the
   `signalCode === 'SIGKILL' || exitCode > 128` heuristic, which could
   misclassify hard-killed children as timeouts and timeouts as crashes.
2. `--timeout` is validated in `parseArgs` before any subprocess spawns:
   must match `/^\d+$/` and be > 0. Floats ("1.5" — previously truncated by
   parseInt to 1!), zero, negatives, and non-numeric input are rejected with
   `LUGAS_CLI_001` RangeError.

Behavioral note discovered while testing: a module ending in
`await new Promise(() => {})` does NOT hang the child (a pending promise
with no handles doesn't hold the event loop); hangs require active handles
(timers/server). Tests use `await Bun.sleep(30_000)` for a deterministic hang.

## Security considerations
Earlier heuristic risked exit-code collision misclassification; property-based
detection is deterministic. Validation prevents subprocess spawns on malformed input.
