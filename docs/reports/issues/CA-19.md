# CA-19 Evidence Report

## Baseline

- Base commit: `61aee0a` (Merge pull request #429 — attested beta.5 packet)
- Branch: `agent/CA-19-preflight-erratum` / Worktree: `.worktrees/CA-19`
- Owner review found two shell-level defects in the generated
  `docs/releases/beta/CHECKLIST.md` publish sequence and prescribed the
  correction. Disposition: retain the candidate, correct the narrow
  preflight, do not rebuild the tarball, publish `beta` only with `latest`
  unchanged.

## Outcome

1. **Defect 1 — unbound variable:** the preflight referenced
   `${BETA_VERSION}` without assigning it; under `set -u` a fresh shell
   aborts at the first reference. Fixed: `BETA_VERSION='0.1.0-beta.5'`
   assigned (builder template renders the candidate version).
2. **Defect 2 — indeterminate absence:** a failed exact-version lookup
   followed by a successful reachability probe could reach the publish
   boundary despite an indeterminate first answer. Replaced with the
   owner-prescribed form: require a successful, well-formed
   `npm view lugas versions --json` response, then check candidate presence
   in-process. With `pipefail`, a failed registry command aborts; malformed
   JSON, non-array, empty, or non-string-entry responses abort; a present
   candidate aborts.
3. **Publish command** now carries `--registry=https://registry.npmjs.org/`
   explicitly; **step 3** verification states the REQUIRED end state:
   `beta -> 0.1.0-beta.5` AND `latest` unchanged (currently
   `0.1.0-beta.4`) — promotion of `latest` is a separate explicit owner
   decision, never incidental.
4. **Step 5 (new) — registry acceptance:** post-publication battery that
   executes the installed package: registry tarball download, digest check
   against `50fd1356…`, `bun add lugas@0.1.0-beta.5`, root/client export
   execution, `bunx lugas --version` identity, and separate `beta`/`latest`
   dist-tag inspection. Metadata lookup alone is not acceptance.
5. **Builder template parity:** `scripts/release/build-beta-packet.ts`
   generates the corrected preflight and step 5 for all future packets;
   the rendered command segments are byte-identical to the committed
   checklist (modulo the intentional `${BETA_VERSION}` → literal
   substitution and the concrete prior-latest comment).
6. **Erratum provenance:** CHECKLIST.md carries an erratum note binding the
   correction to CA-19 and stating that only `CHECKLIST.md` and
   `SHA256SUMS` changed; the tarball and all other packet artifacts are
   byte-identical to the `61aee0a` assembly.
