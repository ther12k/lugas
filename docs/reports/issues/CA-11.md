# CA-11 Evidence Report

Implements the final roadmap item in the owner's sequence: the Vite/React
reference starter built ON the finished hosting contract — in-repository
reference application, deliberately small production target (frontend build
→ static files; server → Bun entry; one process serving typed API + assets +
SPA navigation fallback). Directed by the owner 2026-09-12.

## Baseline

Branch base: origin/main `77a165e` (after CA-10, PR #413). The hosting
contract existed and was tested at the framework level; nothing demonstrated
the end-to-end application shape against the INSTALLED package.

## Outcome

### The starter (`examples/spa-starter/`)

- **Consumer truth**: `scripts/setup.ts` packs the CURRENT checkout into
  `lugas-starter.tgz` (staged copy, version-standin, no worktree/node_modules
  noise — modeled on the M7-005 harness) and installs it into the starter;
  the setup removes the previously installed package AND `bun.lock` (bun
  otherwise resolves `file:` deps through lockfile-cached state and can leave
  stale package sources — found and pinned here). Every starter import
  resolves from `node_modules/lugas`, never the checkout.
- **Build** (`scripts/build.ts`): `vite build` (manifest mode) → asset
  manifest REGENERATED from the Vite manifest as explicit
  `{ path, cacheControl }` mappings (ADR-0037: build-time mapping, no
  runtime scanning) → server entry bundled with `bun build --target=bun`.
  The bundled entry resolves `dist/` from the process working directory
  (`import.meta.dir` does not survive bundling — found and pinned here).
- **Server** (`server/app.ts`): typed hello, zod-validated mutation, cookie
  login + guard-gated `/api/me` (browser-managed cookies, honestly — no
  header plumbing), `form({ repeated: "preserve" })` upload returning both
  the last-wins view and per-name group counts, SSE ticks + heartbeat,
  `secureHeaders`, hashed assets (immutable), `spa` navigations `["/",
  "/app/*"]`. `STARTER_PROFILE=api-only` strips assets/spa for the
  measurement baseline.
- **Frontend** (`src/App.tsx`): typed client GET/POST, typed 422 branch
  handling, multipart via `formBody`, EventSource SSE, deep-navigation view
  hydration from `location.pathname` (nested-route refresh), all against
  `AppContract<typeof app>` — types from the installed package.
- **Correctness tests** (`tests/starter.test.ts`, 8 tests): run the BUILT
  server as a subprocess (direct binary spawn, not `bun run` — the wrapper
  intercepts SIGTERM and masks the graceful exit code) and assert: readiness,
  typed GET, 201 mutation + typed `VALIDATION_FAILED` branch, 401→login→200
  cookie auth with httpOnly, multipart last-wins + groups, SSE wire framing
  (3 ticks + heartbeat) via stream iteration, shell at `/` and
  `/app/projects/42` with identical policy/cache headers, hashed asset
  immutable caching, API-404-stays-API even with `Accept: text/html`, and
  SIGTERM graceful shutdown to exit 0 (ADR-0020). `bun test` from the repo
  root discovers and runs this file; it skips (unless
  `LUGAS_REQUIRE_STARTER=1`) when the starter is not set up.
- **Measurements** (`scripts/measure.ts` → `measurements/2026-09-12-api-vs-spa.json`):
  API-only vs API+SPA from the same server code, pinned to bun 1.4.0, lugas
  source `77a165e…`, and the frontend artifact hash. Results on this
  machine/run: readiness 13 ms (api-only) vs 11 ms (api+spa); idle RSS 8.0
  vs 7.9 MiB; after a 40-round asset/navigation workload 8.0 vs 7.9 MiB;
  both profiles SIGTERM-exit 0. Recorded as measurements to establish —
  the note in the artifact explicitly disclaims savings/guarantees.

### Consumer truth found: DOM-lib type fixes in the package

The starter's standard frontend tsconfig (`lib: ["dom", …]`) surfaced
SEVEN type errors inside the shipped lugas sources that the root project
(no DOM lib) can never see — exactly the class of failure the
installed-package requirement exists to catch:

1. `src/client/request.ts` — `init.body = body` under
   `exactOptionalPropertyTypes` rejected `undefined` under DOM lib; presence
   guard moved to the value (`body !== undefined`; semantically identical).
2. `src/core/response.ts` ×4 — `as Bun.HeadersInit` casts break DOM-lib
   consumers (the Headers constructor takes the DOM HeadersInit); replaced
   with `HeaderSeed = ConstructorParameters<typeof Headers>[0]`, which
   resolves to the ambient HeadersInit of whichever environment typechecks.
   (Naming the bare global `HeadersInit` would break the root project — it
   has no such global.)
3. `src/internal/compression.ts` — `encode()` return widened to
   `Uint8Array<ArrayBufferLike>` while DOM `BodyInit` needs the exact-ArrayBuffer
   view; return type narrowed truthfully (fresh buffer from Bun gzip/deflate).
4. `src/internal/parse-form-body.ts` — same narrowing for the bounded-read
   bytes (`new Uint8Array(n)` is exactly `Uint8Array<ArrayBuffer>`).

No runtime changes; root typecheck and the full suite stay green.

## Assumptions

- Starter tests are discovered by the root `bun test` (cwd walk) and SKIP
  when not set up; the starter's own `bun run verify` is the full lane.
- `bun build --target=bun` bundling the installed TS lugas source is a valid
  production shape for the starter (single built entry; Bun executes it).

## Security considerations

None new — the starter composes `secureHeaders` with the shell (asserted);
auth is a demo in-memory session with an httpOnly cookie and is labeled as
such; no secrets, no network egress beyond npm installs during setup.

## Known limitations / Not exercised

- No real-browser lane for the starter UI (the M7-005 browser lane covers the
  client in a real browser); UI rendering is not asserted, only served bytes.
- `EventSource` is unavailable in the Bun 1.4 test runtime, so the starter's
  SSE test reads the wire stream directly; the frontend itself uses
  EventSource (the documented consumer) at runtime in browsers.
- TanStack Router/Query integration and `create-lugas` scaffolding remain
  deferred (owner: start small, in-repo reference first).
- Measurements are single-run on one Linux machine; the artifact records the
  environment and disclaims comparability.
