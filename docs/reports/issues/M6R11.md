# M6R11 — Preserve throw in array positions; callability-only hook detection (#323)

## Baseline

- `main@6dbaefd` (post-M6R10 merge, PR #322; #321 closed; #315 open).
- Trigger: follow-up review confirming the M6R10 two-phase architecture as correct and finding one release-blocking bug concentrated in the final element-outcome conversion, plus one hook-detection edge. Both reproduced before implementation.

## Findings verified against the exact tree (all confirmed)

1. **P1 — BigInt array elements became `null` in the type.** `JsonifyElement` applied `StripThrows` **before** the drop check, so a raw `JsonThrows` outcome (direct `bigint` or hook→bigint) became `never` and was then classified as a drop → `null`. Probed: `Jsonify<[bigint]>` → `[null]`, `Jsonify<[{ toJSON(): bigint }]>` → `[null]`. Runtime truth: both throw `TypeError` — `SerializeJSONArray` substitutes `null` only for `undefined` results, never for abrupt throw completions. The committed comment stated the correct behavior; the implementation contradicted it. M6R10's tests missed it because they covered hook-bigint in root/member positions only.
2. **P2 — hook detection was signature-sensitive.** The `(key: string) => J` pattern misses e.g. `toJSON(_key: number)`, which JS happily calls (parameter annotations do not exist at runtime; callability is the only test). Probed: runtime `{"value":{"ok":true}}`, type `{}`.

## Outcome

Both fixed; the two-phase architecture is unchanged.

- **Element classification order** (`JsonifyElement`): the raw post-hook outcome is classified before any stripping — raw `never` → drop → `null`; raw `JsonThrows` → throw → `never`; otherwise `StripThrows<R>` (the value). Union element members distribute per-member, so `[bigint | string]` → `[string]` and `[undefined | string]` → `[null | string]`.
- **Callability-only hook detection** (`HookOnce`): `toJSON: infer F` + `F extends (...args: any[]) => infer J` — any callable `toJSON` is a hook regardless of its parameter list; a non-callable `toJSON` stays an ordinary (serialized) member, matching runtime.
- Zero fallout in existing assertions (M6R7–M6R10 suites pass unchanged).

## Assumptions

- A callable `toJSON` with any parameter list is a hook (runtime truth); overloads resolve to their last signature under `infer` — acceptable and consistent with structural inference limits.
- A non-callable `toJSON` member serializes as an ordinary property (both in JS and in the model), unchanged from M6R10's stated treatment — now with the corrected callability test.
