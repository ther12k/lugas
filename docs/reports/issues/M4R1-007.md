## Outcome

Completed. The production error boundary is a plain function — sync stays sync end-to-end; thrown values are never mutated; frozen errors redact safely.

## Assumptions

Recorded before coding:

1. **Non-async wrapper.** `withErrorPolicy()` returns a plain function: sync handlers resolve synchronously inside `try`; only promise-like results take the `.catch` path. Fully-sync descriptors now produce a non-async final Bun route handler, matching the lifecycle spec ("no added Promise chaining when all stages are synchronous").
2. **Thrown values are never mutated.** The old `Object.assign(error, { routeId })` disappears (it throws on frozen errors *inside catch*, bypassing the error policy entirely and risking Bun's dev-page leak). Route identity reaches the policy via wrapper closure instead.
3. **Public `ErrorPolicy` signature unchanged** (`(error, request) => Response | Promise<Response>`). Internally, `withErrorPolicy` dispatches: the framework default receives `(error, request, routeId)` directly; user policies keep the two-argument public shape. Identity check against `defaultOnError` is the dispatch mechanism; a user wrapping/copying the default gets the two-arg public contract and supplies their own route identity if they want one (documented limitation).
4. **Redaction guarantees unchanged**: default policy still logs one line with method/path/route-id and returns the redacted 500 problem; thrown values never reach the response body.
5. **Probes**: frozen Error → redacted 500 AND original error object untouched (`!("routeId" in error)`); rejected-Promise handler → redacted 500; custom onError receives the thrown value unmodified; sync descriptor → non-async final handler.

## Type/runtime/bundle impact

- Public `ErrorPolicy` signature unchanged; `defaultOnError` gains an optional internal third parameter.
- Runtime: one fewer async function allocation per route; sync request paths allocate zero Promises through the boundary.

## Security considerations

- Closes the frozen-error bypass: previously `Object.assign` onto a frozen/non-extensible thrown value threw *inside catch*, skipping the policy and letting Bun's dev page render message + stack. Redaction now cannot be bypassed by throwing immutable values.

## Known limitations

- Dispatch to the three-arg default uses reference identity; a user wrapping `defaultOnError` receives the public two-arg shape and must supply their own route identity. Documented in assumptions (#3).
